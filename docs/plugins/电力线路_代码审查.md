# 电力线路插件 · 代码审查

> **日期**：2026-09-07  
> **范围**：`com.plot.plugin.PowerLinePlugin`、`com.plot.plugin.powerline.*`、对应测试、i18n、用户向导  
> **重点**：逻辑正确性、**UI 与逻辑衔接是否完整**、界面本身问题

## 一句话

电力线路已经从「认领折线 → 立杆 → 下垂导线」长成 **样式卡片 + 杆塔设计器 + 地形避让 + 工程分析** 的完整插件：入口薄、四 Tab 玩家路径清楚、预览指纹做得认真。真正的断点在 **确认弹窗按 ImGui 约定会闪一下就关**、**开地形避让时「计算预览」会静默改线路且不进撤销**、以及 **工程报告 / 加杆约束与界面显示脱节**。

## 架构概览

```
PowerLinePlugin                         生命周期 / sidecar 持久化 / 工程画布叠加
  └ PowerLineUiContext
        ├ PowerLinePluginState          线路工程 + 杆塔设计工程 + 预览指纹
        └ PowerLineActions              认领 / 预览 / 建造 / 工程优化 / 存盘

UI（PowerLineUIManager）
  概览 Overview → 线路 Route（含认领）→ 样式 Style → 建造 Build
  延迟窗口：删除确认 / 建造确认 / 优化确认 / 杆塔设计器

生成
  PowerLineGenerator
    PowerPoleLayoutUtils                强制点 + maxSpacing 插杆 + layoutConstraints
    PoleDesignAssignmentResolver        单杆设计 / 塔族 / 自动选塔
    TowerStructureGenerator | 默认立柱
    ConductorSpanGenerator              多挂点下垂导线
    LineEquipmentGenerator / Jumper
```

玩家主路径（i18n 描述）：画直线/折线 → 认领 → 选间距与风格 → 预览幽灵方块 → 建造。工程分析默认关闭，藏在建造 Tab 的「高级检查」里。

| 界面入口 | 调用的逻辑 | 衔接状态 |
|----------|------------|----------|
| 线路 Tab · 认领 / 拾取路径 | `PowerLineActions.adoptSelectedPaths` / `activatePathPickTool` | **部分**：拾取只是切到通用 `select` 工具，没有道路那种 Pick Session |

| 样式 · 高级 · 杆型 / 塔族 / 角色 | `setPoleDesignId` / `setTowerFamilyId` / `PowerLineOverrideUtils` | **完整**；塔族会清空单杆设计 id |
| 样式 · 打开设计器 | `PoleDesignerPanel.open` → `savePoleDesign` | **完整**；设计工程单独存 `pole-designs/` |
| 建造 · 计算预览 | `calculatePreview` → `generator.generate` → 投影幽灵 | **有副作用**：地形避让开启时会改 footprint |
| 建造 · 建造 / 确认 | `requestBuildConfirm` → `buildInWorld` → `PowerLineGenerateCommand` | 预览指纹校验是对的；**确认弹窗调用方式有问题** |
| 建造 · 友好状态 | `PowerLineFriendlyStatus` + 缓存的工程/地形报告 | **会显示过期报告**（清预览不清报告） |
| 建造 · 智能修正 | `runTerrainAvoidance` / `proposeClearanceFix` / `proposeAutoTowerSelection` | 逻辑在；**加杆结果界面看不见、也删不掉** |
| 建造 · 高级检查 | `analyzeEngineering`、规则 profile、画布 overlay | **能用，但入口深**；独立 Engineering Tab 的 `render()` 已死 |
| 概览 · 杆数 / 地图杆位 | `estimatePoleCount` / `computePolePositions` | **不含** `layoutConstraints`，和真实生成不一致 |
| 工具栏撤销 | `projectHistory.undo` | **不含** 杆塔设计工程；地形避让若没 push 则无法撤 |

## 问题清单

### P1 — 玩家主路径会错或操作无效

#### P1-1 确认弹窗只在「pending 那一帧」调用 `beginPopupModal`

**位置**

- `PowerLineOverviewPanel.renderDeleteConfirmPopup`
- `PowerLineGeneratePanel.renderBuildConfirmPopup`
- `PowerLineEngineeringPanel.renderOptimizationConfirmPopup`
- `PoleDesignerPanel.renderPresetConfirmPopup`

共同写法：

```java
if (!ctx.deleteConfirmPending()) {
    return;          // 后续帧根本不会再 beginPopupModal
}
ImGui.openPopup("##powerline_delete_confirm");
ctx.setDeleteConfirmPending(false);
if (ImGui.beginPopupModal(...)) { ... }
```

ImGui 要求弹窗打开期间 **每帧** 调用 `beginPopupModal`。pending 被立刻清掉后，下一帧函数直接 return，弹窗会关掉。删除 / 建造 / 智能修正 / 加载预设 都可能「闪一下就没了」，玩家点不到确认。

**建议**：始终调用 `beginPopupModal`；只在 pending 为 true 时 `openPopup`：

```java
if (pending) {
    ImGui.openPopup(id);
    pending = false;
}
if (ImGui.beginPopupModal(id, ...)) { ... ImGui.endPopup(); }
```

#### P1-2 「计算预览」在地形避让开启时会改线路，且不进撤销

**位置**：`PowerLineActions.calculatePreview` → `runTerrainAvoidance` → `TerrainAvoidance.applyOneFix`

建造 Tab 的「计算预览」会：

1. 生成一次
2. 若 `isTerrainAvoidanceEnabled()`，最多 4 轮 `applyOneFix`（换更高塔 / 加高电杆 / `addLayoutConstraint` 插杆）
3. 再次生成

「智能修正 · 地形自动调整」按钮会先 `pushEditSnapshot()`，普通预览按钮 **不会**。玩家只是想看幽灵方块，线路参数已经被改掉，撤销栏还是空的。

**建议**：预览必须只读。自动修正只走「智能修正」按钮，并且先 push 历史。

#### P1-3 工程 / 地形报告在预览失效后仍显示

**位置**：`PowerLineActions.clearPreview` / `invalidatePreview` **不清理** `PowerLineEngineeringUiState` 的 `lastEngineeringReport` / `lastTerrainReport`。

`PowerLineBuildPanel.renderFriendlyStatus`：

```java
LineEngineeringReport report = ctx.state().getEngineeringState().getLastEngineeringReport();
if (report == null && ctx.hasValidPreview(line)) {
    report = ctx.actions().analyzeEngineering(line);
}
```

改间距 / 垂度后预览被清掉，状态区仍用上一轮报告，可能继续显示「导线擦地」或「全部正常」。画布叠加用了 `previewKey.matches`，所以叠加层会消失，**面板文案和叠加层还不一致**。

另外：`report == null && hasValidPreview` 时在 **渲染线程** 跑完整工程分析 / 地形碰撞，第一次打开建造 Tab 可能卡一下。

**建议**：`clearPreview` 同时清两份报告；展示前校验 `lastAnalyzedFootprintId` + 与 `previewKey` 一致；分析放到按钮或预览成功回调，不要放在 `render()`。

#### P1-4 加杆约束没有界面，概览杆位也不画它们

优化「插入中间杆」和地形避让都会 `line.addLayoutConstraint(...)`。布局层 `PowerPoleLayoutUtils.computePoleSites(footprint)` **会吃** 这些约束。

但界面：

| 表面 | 实际用的 API | 结果 |
|------|----------------|------|
| 概览「杆数」 | `estimatePoleCount()` → `computePolePositions`（无约束） | 比真实少 |
| 概览地图 / 缩略图杆点 | 同样 `computePolePositions` | 插进去的杆看不见 |
| 线路 / 样式 / 建造 | **没有任何** 约束列表或删除按钮 | 插杆后只能靠撤销（如果当时有 push） |

**建议**：概览改走 `computePoleSites(line)`；高级区列出强制杆位，允许删除单条约束。

#### P1-5 「最小间距」滑条不参与立杆

线路 Tab 高级里有 min / max 两个滑条，间距卡片也会写入 `minPoleSpacing`。`PowerPoleLayoutUtils.computePolePositions` **只使用 `maxPoleSpacing`**。min 只出现在：

- `hasMinSpacingWarning`（强制拐点过近）
- `PowerLineFriendlyStatus.evaluateSpacing`（生成后诊断）

玩家以为「最小间距 10」会保证杆距 ≥ 10，拐角处仍然会并杆，然后建造页报「过近」。不是滑条坏了，是控件语义和布局算法不是一回事。

**建议**：要么布局尊重 min（合并过近强制点 / 拒绝），要么 UI 改成「仅告警，不改变立杆」。

#### P1-6 工程能力入口断了，独立面板变成死代码

`PowerLineUIManager` 只有四个 Tab：`overview / route / style / build`。

仍存在但 **不再作为 Tab 挂上去** 的完整 `render()`：

- `PowerLineGeneratePanel.render()`
- `PowerLineEngineeringPanel.render()`
- `PowerLineUiWidgets.renderAdvancedEngineeringSection()`

工程开关、规则 profile、画布叠加，只在建造 Tab 底部折叠的「高级检查」里。默认 `engineeringAnalysisEnabled = false`、`overlayEnabled = false`。智能修正整段在分析未开且地形避让未开时直接 `return`。

i18n 还留着 `plugin.powerline.tab.adopt / edit / generate`，代码已不用。用户向导 `docs/zh/08-plugins.md` **完全没有电力线路**，仍写「所有插件都是概览 / 认领 / 编辑 / 生成」。

**建议**：要么给工程一个明确折叠「专业检查」（默认关），要么删掉死 `render()`；用户向导补一节，与四 Tab 对齐。

#### P1-7 清除选择不撤幽灵方块

概览「清除选择」只 `selection().clear()`，不走 `selectLine` / `invalidatePreview`。世界里上一轮幽灵还在，建造 Tab 却提示「请先选择线路」。

**建议**：clear / selectAll 若 primary 变化，走 `actions.selectLine` 或显式 `invalidatePreview`。

## 值得保留

1. **四 Tab 玩家路径**（概览 / 线路 / 样式 / 建造）比旧的认领/编辑/生成更清楚；风格和垂度用卡片，默认把工程折叠起来，方向对。
2. **`PowerLinePreviewKey`**：线路指纹 + 设计工程 JSON hash，避免用过期幽灵建造。`PowerLineStabilizationTest` 锁了这条。
3. **生成与建造同源** `lastGenerationResult.placementRecords`，落地走 `PowerLineGenerateCommand`，可撤销世界写入。
4. **插件入口瘦**，失败即 throw，没有道路那种「生成器初始化失败还继续启用」。
5. **杆塔设计器独立窗口** + `pole-designs/` sidecar，内置设计另存为新 id，避免改坏 catalog。
6. **认领拒绝曲线**（Bezier 单独列表），不和可认领折线混在一起。
7. **原子写盘 + ContentFingerprint**，线路与设计工程分开跳过无变更保存。
8. **塔族 / 角色 / 多挂点导线** 领域模型完整，测试覆盖生成、塔结构、工程分析、legacy 兼容，比 UI 厚。

## 改造建议

### 短期（先修玩家能感知的衔接）

1. 所有确认弹窗改为「每帧 `beginPopupModal`」（P1-1）。
2. 预览只读；地形自动改线只走智能修正，并且先 push 历史（P1-2）。
3. `clearPreview` 清工程/地形报告；状态区绑定当前 `previewKey`（P1-3）。
4. 概览杆数 / 地图改 `computePoleSites(line)`；高级里列出并可删除 `layoutConstraints`（P1-4）。
5. 最小间距：改文案或真正约束布局（P1-5）。
6. 清除选择 / 全选变更 primary 时失效预览（P1-7）。
7. 用户向导补「电力线路」一节，与现四 Tab 对齐（P1-6）。

### 中期

1. 删或挂上死掉的 `GeneratePanel.render` / `EngineeringPanel.render`；工程入口做成建造页一个折叠，不要让人以为还有第五个 Tab。
2. 拾取路径做成真正的 session（高亮可认领折线，回车认领，Esc 取消）。
3. JSON 加 `schemaVersion`；设计变更进入可撤销快照，或明确「设计器无撤销」。
4. 工程 overlay 仅在本插件为当前扩展时绘制。
5. 生成警告全部 i18n；角色 combo 修到 6 项。

## 测试缺口

| 缺口 | 现有覆盖 |

| 确认弹窗跨帧 | 无 UI 测试 |

生成 / 塔族 / 导线 / PreviewKey 的单测是够用的，**缺的是 UI Actions 这一层**。
