# 建筑轮廓生成器 · 代码审查

> **日期**：2026-09-07  
> **范围**：`com.plot.plugin.BuildingPlugin`、`com.plot.plugin.building.*`、对应测试、产品定位与 golden harness  
> **性质**：只读审查。历史报告仅作背景；下列问题均以当前代码核对。

## 一句话

Massing v1 已拆成「Plugin 生命周期 + Pipeline stages + Spec 解析 + UI Actions」，片区 fail-soft / later-wins 主路径可用；真正的 God class 已从 `BuildingGenerator` 挪走。编辑主路径仍直接改 `BuildingFootprint`，**加门滑条跨帧失效**，Golden / Benchmark **几乎不碰世界采样与土方垫层**，所以产品声称的「场地 / 垫层 / 街区规模」语义并未被测试锁死。

## 架构概览

```
BuildingPlugin                            生命周期 / sidecar 持久化
  └ BuildingUiContext / BuildingActions / Panels
        └ BuildingGenerator（门面，~60 行）
              └ BuildingGenerationPipeline
                    SitePrep → Foundation → Wall → Floor → Roof → Accessory → Opening
              └ DistrictMassingGenerator（fail-soft + 合并 later-wins）

生成前解析
  BuildingFootprint  --Mapper--> BuildingDefinition (spec)
  MassingGeometryResolver / FloorPlateGeometryResolver
  GenerationSiteResolver（manual > earthwork pad > terrain）
  MaterialResolver
```

产品准绳：`docs/development/BuildingPlugin_产品定位.md`（2026-09-07 Stabilized / Feature Complete）。默认 UI 以 Massing / Blockout 为第一优先级；门窗 / 立面在高级折叠里。

## 问题清单

### P1 — 编辑主路径失效 / 垫层语义分叉 / 测试锁不住屋顶

#### P1-1 加门 UI 的边 / 位置 / 层滑条每帧重置

**位置**：`BuildingEditPanel.renderDoorEditor`

```411:425:src/main/java/com/plot/plugin/building/ui/BuildingEditPanel.java
        int[] wallSegment = {0};
        float[] positionRatio = {0.5f};
        int[] floor = {0};
        ImGui.sliderInt(..., wallSegment, ...);
        ...
        if (ImGui.button(...add_door...)) {
            building.addOpening(OpeningSpec.door(
                wallSegment[0], positionRatio[0], floor[0], 1, 2));
```

每帧把 draft 清成墙段 0、比例 0.5、1 层。ImGui 滑条跨帧状态被丢掉。「添加门」几乎永远写成默认洞。阳台滑条从 model 读回，所以能改；门编辑器不能。

**建议**：把 draft 放到 `BuildingPluginState`（按当前建筑 id 存 `ImInt` / `ImFloat`），`add_door` 读 draft。

#### P1-2 EARTHWORK_OWNED 垫层解析失败时静默退回地形，UI 却显示「已关联」

**位置**

- `BuildingSiteElevationResolver.resolveEarthworkPadElevation` → `PluginManager.getInstance().getPlugin("earthwork_balance")`
- `BuildingPadElevationService.resolveEarthworkOwnedPadElevation`：无显式标高且无 `previewGrid` → `Optional.empty()`
- `GenerationSiteResolver.decide`：`resolvedPad == null` → `FoundationElevationSource.TERRAIN`
- UI：`BuildingEditPanel.renderEarthworkPadElevationHint` 在 pending 时仍显示 linked

产品优先级是 `manual > pad > terrain`。用户按 UI 以为 ±0 跟垫层，实际跟地形，**不会**写 `plugin.building.warn.using_earthwork_pad_elevation`。垫层值还可来自土方「上次预览网格」，换场地后可能吃旧数据。

**建议**

1. pad 已关联但值为空时不要假装 TERRAIN；生成结果加明确 warning（与 UI pending 同一 i18n）。
2. 有显式 `DesignSurface.elevation` 时不依赖 last earthwork preview。
3. 网格必须带 site / zone 指纹，不匹配则视为 unresolved。

#### P1-3 片区预览 / 生成在 UI 线程同步跑完整管线 + 世界采样

**位置**：`BuildingActions.calculateDistrictPreview` → `buildingGenerator.generateDistrict(buildings, world)`

生产路径对每栋做 `BuildingSiteAnalyzer.analyze`（逐格 `sampleColumn`）+ 默认 Pipeline。Benchmark D05（500 栋）是 **`forTesting`、无 World**，~541 ms；有世界时是另一数量级。产品定位就是「几十到几百栋」。主线程同步会卡预览 / 点击。

**建议**：片区生成搬到现有 `placement` / scheduler 异步；UI 显示 progress；CI 加「带伪 World 采样」的规模门（100 栋即可）。

#### P1-4 Golden 分类把坡屋顶方块算进墙，屋顶语义几乎没锁住

**位置**：`GoldenBuildingMetricsCollector.collect`：先 `wallId` 再 `roofId`

默认墙 / 屋顶都是 `minecraft:stone_bricks`。Expectations：

- B03 HIP：`roofBlocks = 0`，`wallBlocks = 112`
- B06 / B12 GABLE：`roofBlocks = 0`，只锁了 `effectiveRoofType`

Regression 刷新 snapshot 时，坡顶几何坏了只要总数还在 wall 桶里也能过。`SemanticAcceptanceAssertions.hasDisconnectedRoof` 用 `getRoofBlockId()`，墙顶同材质时会把整圈墙柱当屋顶连通域。

**建议**：Case 工厂给屋顶单独材质；collector 按 stage / Y 分类；B03 / B12 断言 `roofBlocks > 0` 且屋顶 AABB 高于墙顶。

### P2 — 模型 / UI 缺口 / 耦合

#### P2-1 认领把 `isRectangular` 写成 `isSlopedRoofEligible`

**位置**：`BuildingActions.adoptSelectedFootprints`

```470:472:src/main/java/com/plot/plugin/building/ui/BuildingActions.java
            boolean rectangular = BuildingGeometryUtils.isSlopedRoofEligible(validation.cleanedPoints());
            BuildingFootprint footprint = new BuildingFootprint(validation.cleanedPoints(), rectangular);
```

已有 `detectRectangular` / `isAxisAlignedRectangle`，生产代码从未调用。骨架能出坡顶的 L / 旋转矩形会被标成 rectangular；太窄的真矩形可能标成 false。生成已改用几何 eligibility，不读这个 flag；但 JSON / `FootprintSpec.rectangular()` 会脏。

**建议**：认领用 `detectRectangular`；坡顶资格只走 `isSlopedRoofEligible`。

#### P2-2 JSON 单栋非法轮廓被静默丢掉

`BuildingProject.ProjectData.toProject`：`outerPoints.size() < 3` → `continue`。损坏 JSON 会抛；**合法 JSON 里的坏栋**直接跳过，项目变少且无 warning。撤销栈也是 JSON 深拷贝。

**建议**：收集 skipped + 原因；load 失败策略显式化。

#### P2-3 FloorPlate / 分墙立面有模型与管线，Edit UI 接不上

`BuildingEditPanel.renderAdvancedDetails` 的 `floor_plate` 节点 **只改楼板材质**。全 `building/ui` **零处** `setFloorPlates` / `wallFacades`。产品文档把 FloorPlate 放在高级细节；玩家无法做裙房 / 塔楼，只能靠 JSON / 测试。

**建议**：要么做最小 FloorPlate UI（inset / 楼层范围），要么文档改成「引擎能力、默认 UI 不暴露」。

#### P2-4 `FacadeEdgeResolver.sameTopology` 只比顶点数

基础矩形与缩小矩形都是 4 点 → 当同拓扑，用 raw index，**不做方向继承**。边顺序 / 起点不同时，门窗会落到错误立面。

**建议**：同顶点数仍走 `inheritByDirection`。

#### P2-5 窗高 UI 与生成 clamp 不一致

`OpeningGenerationStage.carvePatternWindows`：`maxWindowHeight = floorHeight - sill - 1`。默认层高 3、窗台 1、窗高 2 → 实际 **1 格**。滑条不反映。

#### P2-6 雨篷只能开关；阳台只编第一项且拖动不进历史

`renderCanopySettings` 勾选即 `addCanopy` / 清空，无 width / depth。`renderBalconySettings`：`isItemActivated` 紧跟 checkbox，滑条改值不 `push` 历史。与 P1-1 同一类即时 UI 问题。

#### P2-7 建筑 ↔ 土方编译期环，且无 schemaVersion

- `BuildingSiteElevationResolver` → `EarthworkPlugin` → `BuildingPadElevationService` → `BuildingFoundationUtils`
- `BuildingProject` JSON **没有** `schemaVersion`。`BuildingProjectPersistence` 只是 `toJson` / `fromJson` 门面，format v2 时没有迁移钩子。道路 / 土方都有。

#### P2-8 场地分析失败仍按 Y=64 生成

`BuildingSiteAnalyzer.analyze` `catch (Exception)` → `failedFallback()`；`GenerationSiteResolver` 用 `DEFAULT_GROUND_ELEVATION`。有 `site_analysis_failed` warning，但 foundation 仍切填到默认海平面附近。

**建议**：分析失败且无 manual / pad 时跳过该栋（记入 district skipped）。

#### P2-9 双模型：UI 写 Footprint，生成读 Definition

`BuildingFootprint` 仍是可变 God DTO（类注释已写冻结线）；`BuildingDefinition` 只在 generate 时 `fromFootprint`。`applyMassingEnvelopeFacadeRoofFoundation` 几乎只给测试用。

**建议**：中期冻结 Footprint 字段；新语义只进 spec。短期不要再往 Footprint 加 setter。

#### P2-10 片区重叠 O(n²) 只对成功栋；later-wins 测试是桩数据

`DistrictOverlapAnalyzer.findFootprintOverlapPairs` 两两相交。`BuildingDistrictScenarioTest.districtOverlapLaterWins` 自己 `put` 两个 BlockRecord，**不跑 Pipeline**。

**建议**：两栋真实重叠 footprint 走默认管线，断言合并格 `newBlockId` 与 `previousBlockId`。

#### P2-11 其它

| 项 | 说明 |
|----|------|
| 无 `BuildingConfig` | 道路 / 土方都有插件配置；建筑默认参数散落在 Footprint 常量 |
| `BuildingActions` ~533 行 | persist / preview / generate / batch / adopt 挤在一起 |
| 片区虚影不加抽稀 | 土方 >4000 抽稀；建筑片区全量 `addGhostBlocks`，几百栋会卡 |
| ADR 0001 | `BuildingSiteElevationResolver` 用 `PluginManager.getInstance()` |

## 值得保留

1. **Pipeline 顺序清晰且有文档**：Opening 在 Accessory 后，可穿透外挑；inner-offset 降级写在 `InnerOffsetDegradation`，Wall / Floor / Opening / Roof 行为一致。
2. **`DistrictMassingGenerator` fail-soft** 与产品「100 栋中 3 栋 invalid → 97 generated + 3 reported」一致；单栋 `catch (Exception)` 不 abort。
3. **标高三分开**（`requested` / `resolvedPad` / `actual` + `FoundationElevationSource`）方向正确；manual 压过 pad；循环依赖在土方侧被切断。
4. **`BuildingBlockWriter` 保留首次 `previousBlockId`**，stage 覆盖 `newBlockId`，撤销语义正确。
5. **`FloorPlateSchedule` 禁止 silent `getLast()`**，缺口用 base 填并 warning。
6. **UI 分层**：Plugin / State / Actions / Panels；Massing-first（基础展开、细节折叠）符合产品定位。
7. **B07 语义测试与 snapshot 分离** 是对的（零墙体曾被写进 expected）。
8. **场地清理保守**：无树冠原木不删，记 structure conflict；树 BFS 有 256 / 半径上限。
9. **Deprecated Batch A 已清干净**，比道路 / 土方更彻底。

## 改造建议

### 短期（1–2 周，不重构 Pipeline / Spec）

1. 修门 draft 状态（P1-1）；雨篷 / 阳台历史与编辑（P2-6）。
2. Pad unresolved 与生成决策对齐（P1-2）；去掉「UI linked、生成 terrain」的分叉。
3. Golden 屋顶单独材质 + `roofBlocks > 0`（P1-4）；B03 / B12 才算锁住坡顶。
4. 认领改用 `detectRectangular`（P2-1）。
5. 片区预览至少 off-thread 或分帧（P1-3），100 栋不要卡死点击。

### 中期

1. `IPadElevationService` 打断 building ↔ earthwork 编译环；垫层查询带 site 指纹。
2. FloorPlate 最小 UI，或文档降级为非默认能力。
3. 生成上下文以 `BuildingDefinition` 为唯一语义源；Footprint 只做 persistence DTO，并补 `schemaVersion`。
4. 带伪 World 的 district harness（采样 + site prep + foundation），Benchmark 才代表生产路径。
5. JSON 部分失败可见；`FacadeEdgeResolver` 不要用顶点数当同拓扑。

## 测试缺口（Golden 锁了什么 / 没锁什么）

**锁住了（无 World 的 `forTesting`）**

- B01–B12 方块计数回归（容差全 0）
- B07 inner-offset 实心墙、无室内楼板、坡顶降级（semantic，不能靠刷新 snapshot 代替）
- B10 厚墙 bounds 非负
- B11 有门窗空气且邻墙
- D-B10 / 11 规模 generated、D-B13 fail-soft、D-B14 混手动标高（仍是 `forTesting`）
- D-B12 later-wins **仅合并层桩数据**
- 校验器、JSON round-trip、部分 foundation 填水柱（手造 column sample）

**没锁住（不要以为「245 tests」覆盖了这些）**

| 语义 | 现状 |
|------|------|
| 土方垫层优先级 | `GenerationSiteResolverOwnershipTest` 的 testing 路径 **pad 恒为 null** |
| SitePreparation 清树 / 草 | 无 World → no-op；cleaner 只有 BFS 单测 |
| 真实地形采样 / 未加载区块 | 无 |
| 生产 `generateDistrict(world)` | UI 主路径无测试 |
| 两栋真实重叠的 Pipeline later-wins | 无 |
| FloorPlate 裙房 → 塔楼 + 门窗方向继承 | 仅 interaction 矩阵有生成 |
| 开洞实际窗高 clamp | 无 |
| 认领 `isRectangular` | 无 |
| JSON 跳过坏栋 | 无 |
| 门编辑器跨帧状态 | 无 UI 测试 |

**结论**：Golden 是「无世界体量计数回归 + 少量手写不变量」，**不是** 场地 / 垫层 / 街区生产语义的契约。刷新 `GoldenBuildingSnapshotGeneratorTest` 尤其危险：当前 collector 会把坡顶算进墙。
