# 道路系统插件 · 交叉口与纵断面审查

> **状态**：历史（2026-10-16）。当前结论见 [道路系统_代码审查.md](道路系统_代码审查.md)（2026-10-23）。  
> **范围**：平交 / 立交 / 单路径自交生成，纵断面编辑后重算  
> **代码**：`com.plot.plugin.road.crossing.*`、`RoadJunctionGenerator`、`pipeline.corridor` 路口清场、`GradeSeparationPolicy`、`VerticalProfileEditor`、`RoadGeneratePanel`  
> **结论（修复后）**：平交铺面已压成单一 `junctionY`；路口柱按残留占用打 AIR，立交净空井卡在 `elevatedDeckY-1`。边合并现在同步拷贝图层，路口 `CLEARANCE` AIR 能盖住残留衬砌。纵断面确认会重算全网预览。自交可在路径 Tab / 叠加 / 纵断面里改平交或立交。`com.plot.plugin.road.*` 1477 测过，交叉口相关（含隧道丁字口中心柱）已绿；仍失败的 2 条是断面预览边坡和走廊桥跨掩膜，与本轮无关。

## 交叉口架构（当前）

```
RoadCrossingReconciler / RoadStackCrossingReconciler
        │  几何相交写入注册表，不改 live 拓扑
        ▼
RoadCrossingMaterializer.materializeForSnapshot
        │  两路交叉 → 共享节点 + node.isGradeSeparated / elevatedRoadId
        │  自交     → 拆边 + breakJunctionSelfLoops → 四臂
        │            node.isStackGradeSeparated / stackUpper|LowerEdgeIds
        ▼
RoadNetworkGenerator  先边后路口
  边：走廊清场（GradeSeparationBuildContext 保护下穿 y≤floorY）
  路口：RoadJunctionGenerator（degree≤2 跳过；立交跳过上跨臂）
        JunctionCellElevationResolver  每格插值
        JunctionCrossSectionFill       铺面
        JunctionTerrainClearance       世界 isSolidBlock 开挖
  合并：边 putIfAbsent，路口 flushJunctionSolids 按层覆盖
```

| 类型 | 注册 | 节点元数据 | 生成意图 |
|------|------|------------|----------|
| 两路平交 | `RoadCrossing` `AT_GRADE` | 共识 `junctionY` | 路口同一标高平面 |
| 两路立交 | `GRADE_SEPARATED` | `isGradeSeparated` + 上跨路 + 净高 | 下穿铺面；上跨走走廊；净空 `clearance` |
| 自交平交 | `RoadStackCrossing` 默认 `AT_GRADE` | 四臂、无 stack 立交旗 | 与十字平交相同 |
| 自交立交 | `GRADE_SEPARATED` | `isStackGradeSeparated` + 上下臂 | 下穿铺面；上臂走廊抬升 |

检测器 `RoadStackCrossingDetector` / `RoadCrossingDetector` 一律写出平交；立交只能事后改注册表。

| 玩家看到的 | 代码位置 | 级别 |

## 证据

### P0 平交不是一个平面

`JunctionCellElevationResolver.resolve`（`pipeline/corridor/JunctionCellElevationResolver.java`）：

- 中心格用路网共识 `junctionY`
- 距中心 `< blendRadius` 时 `smoothStep` 混入引道 `buildProfile` Y
- 测试 `peripheralCellInterpolatesFromApproachProfiles` 明确要求外围格 `y > 68`

平交定义是：不论几条路，都在同一个标高平面过交点。引道纵坡应在路口多边形外衔接，不应在铺面内插值。十字、丁字、多路汇合、自交平交都走这条铺面。

### P0 清场打不掉已生成的路

边在路口之前落地。走廊清场按设计面以上清世界障碍；立交上跨边在保护区内 `y≤floorY` 不挖。

路口清场 `JunctionTerrainClearance.clearOverheadInPolygon` 转给 `RoadTerrainClearanceUtils.applyClearance`：

- `classify`：`surfaceY <= roadY` 则 `NONE`
- `CUT` 只在 `terrain.isSolidBlock` 为真时写 `TUNNEL` 层 AIR

后果：

1. 草、装饰、施工占位（走廊用 `hasObstruction`）路口不管
2. 边留下的 ROAD/FILL/BRIDGE 不在地形采样里，不会被挖
3. 路口 ROAD 在 Y=64、边 ROAD 在 Y=70 是两个 BlockPos；`recordByLayerPriority` 无法互相覆盖

`RoadSolidLayerPriority`：`TUNNEL(8) > BRIDGE(7) > ROAD(3)`。路口只要在同一格柱 `cellY+1…topY` 写出 AIR，合并时可以压掉错层路面。立交必须把 `topY` 卡在上跨桥面之下（`floorY - 1`，与 `GradeSeparationBuildContextFactory` 的 `floorY = underpassY + ceil(clearance)` 一致）。

### P0 立交净空井

`collectUnderpassJunctionEdges` 已跳过 `elevatedRoadId` 和 `isStackUpperEdge`。下穿铺面生成后，交点 XY 上仍叠着上跨走廊。需要：

- 下穿面 `junctionY` 铺路
- `junctionY+1` 到 `elevatedDeckY-1` 无条件打 AIR（净高）
- `elevatedDeckY` 留给上跨，禁止路口 AIR 打穿桥面

`GradeSeparationBuildContext.protects` 已经阻止上跨边挖穿下穿；缺的是下穿路口把中间净空打开。

### P1 纵断面确认不重算

`VerticalProfileEditor.setOnAlignmentCommitted` 在 `confirmWindowSession` 成功后调用。`RoadGeneratePanel` 构造函数只设了 `setFlatOverlayResolver`。

确认路径：

1. `ProfileEditorNetworkApplier.apply` 写回 VA / 节点立交 / `RoadCrossing`
2. `markBuildPreviewStalePreservingProfile`
3. 窗口关闭

灰色「实际道路」折线来自上次预览采样。用户要的是：改完纵断面图 → 再算一次 → 看到生成道路大致走向。应对齐生成 Tab 的「重新计算预览」，接到 `previewManager.startNetworkPreview`。

窗口内体素预览（`autoVoxelPreviewCountdown` / `update_voxel_profile`）只服务编辑器内部，不是路网走向。

### P1 自交没有编辑入口

| 入口 | 两路 `RoadCrossing` | 自交 `RoadStackCrossing` |
|------|---------------------|--------------------------|
| 路径 Tab 列表 | 有 | 无 |
| 画布 / 总览点击 | `IntersectionOverlaySource.CROSSING` | 无 |
| 立交控件 | `renderCrossing` | 无 |
| 纵断面交叉点 | `collectFromCrossings` | 无 |
| 确认写回 | `applyCrossingState` | 无 |

检测默认 `RoadStackCrossing.atGrade`。`setStackCrossingGradeSeparation` 和物化四臂、上/下臂分配已经存在，生成测试 `gradeSeparatedStackCrossingKeepsUpperSurfaceAboveUnderpass` 覆盖了 API 路径。玩家在 UI 里不能把 8 字自交改成立交。

`ProfileEditorNetworkApplier.nodeVerticalStateDiffers` 也不比较 `isStackGradeSeparated` / `stackCrossingClearance`。

### P2 校验与拆环

`JunctionFinalVoxelValidator.countCrossLayerLeaks`：非 `isGradeSeparated` 直接 0；上带从 `junctionY+6` 起算。自交立交漏检；净高不是 6 时会误报路口净空井。

`RoadJunctionGenerator`：`degree <= 2` 不铺路口。自交若 `breakJunctionSelfLoops` 找不到内部折点，会留下自环，路口被跳过。

## 拟改（本轮）

1. 路口铺面一律用共识 `junctionY`，取消格内引道插值。
2. 路口柱清场：世界障碍 + 边残留占用；平交打到 `max(地表, 残留顶)`；立交（含自交立交）打到 `elevatedDeckY - 1`。
3. 纵断面确认成功后启动全网预览。
4. 路径列表 / 叠加 / 立交控件 / 纵断面交叉点 / 确认写回补上 `RoadStackCrossing`。
5. 校验把自交立交和真实净高算进漏层检测。
6. 测试：平交同平面、残留路面被 AIR 覆盖、立交桥面保留、自交平交/立交生成、确认回调触发预览。

不在本轮：边坡包络、画布整数 span、浅桥铺板、玩家原木清场（产品锁）。

## 续修（2026-10-16，玩家五条症状）

| 症状 | 原因 | 修复 |
|------|------|------|
| 交叉点另一条路 Y 断崖 | 边在路口多边形内被 trim，但 snap 半径（约 8）小于 skip（路宽+圆角，常 >12）。修剪边界处完全不 snap，铺面在 `junctionY`、引道还在剖面 Y | `EndpointElevationSnap.coreRadius` = trim skip；核心区内硬对齐路口 Y，过渡带再缓入 |
| 平交不能连通 | 同上：引道与路口面错层 | 修剪边界处 Y = 路口面 |
| 立交下穿错位/堵塞 | 上跨强制标高用下穿**自然**地面，不用路网共识 `networkY`；净高和铺面、保护井对不齐 | `resolveElevatedCrossingHeight(..., networkUnderpassY)`：上跨 = 下穿共识 Y + 净高 |
| 绿线改了纵断面不跟 | `MANUAL_PROFILE` 仍走 `GradeLimitedProfileSolver.projectOntoFeasibleDomain` + 坡度光栅，把用户 PVI 压扁 | 手动模式 `followDesign`：建造 Y 跟设计线；坡度只作校验 |
| 浅隧道/洞门把树换成衬砌 | 衬砌无条件落地；`TunnelRoofGapSealer` 从拱顶填到树冠 | 衬砌只放在地表以下的实心土石，装饰/树木不换；封顶不超过 `sampleSurfaceY` |
