# 道路系统插件 · 代码审查

> **日期**：2026-09-07  
> **范围**：`com.plot.plugin.RoadSystemPlugin`、`com.plot.plugin.road.*`、`RoadSystemConfig`、对应测试与 ADR 0003–0008  
> **性质**：只读审查。历史报告（`docs/historical-reports/`）仅作背景；下列问题均以当前代码核对。

## 一句话

道路插件已经从「画线认领 + 生成」长成 **ADR 0007 三层几何（Design HA/VA → Derived 中心线 → Topology）+ 桩号 / 管线 / 工程检查** 的专业内核：入口薄、测试面广。真正的风险集中在 **失败路径会留下脏路网**、以及 **土方采样在无纵断面时落到默认海平面**（路口与边生成几何双轨问题已于 2026-09-07 修复，见下）。

## 架构概览

```
RoadSystemPlugin                         生命周期 / 土方面向查询
  ├ RoadNetworkManager                   live 单写者：拓扑、选择、撤销、认领
  ├ RoadPersistenceManager               sidecar JSON + fingerprint + 原子写
  ├ RoadPreviewManager                   预览 / 虚影 / GenerateRoadCommand 落地
  ├ RoadToolManager                      路径拾取
  └ RoadUIManager                        Overview / Adopt / Edit / Generate

RoadNetwork                              图 + 工程对象 + JSON（仍偏大）
  Road / RoadEdge / RoadNode
  HorizontalAlignment / VerticalAlignment / 变截面 / 站区设施 / Stationing

生成
  RoadNetworkGenerator
    → DerivedCenterlineSynchronizer      可能写 live 派生折线
    → NetworkNodeElevationResolver       两遍节点标高
    → RoadGenerator（门面）
         → RoadEdgeBuildOrchestrator     纵断求解
         → RoadGenerationPipeline        采样 → 桥隧分类 → 横断面 → 标线/设施 → 边坡 → 体素
    → RoadJunctionGenerator              degree ≥ 3
```

插件入口约 200 行，职责切分（Manager / pipeline / alignment / station）清楚。真正的大块仍是 `RoadNetwork`（约 1143 行，模型 + 序列化 + 拆并路）和 `RoadGeometryUtils`（约 894 行）。

**Generation 几何原则（已 enforce）**

```
Design HA / VA
      ↓
RoadPlanGeometry.resolveEdgeCenterline(...)
      ↓
RoadEdgeBuildOrchestrator ─┐
RoadJunctionGenerator       ├─ 同一条解析几何
RoadJunctionMarkingGenerator┘
```

`RoadJunctionGeometry` 为纯几何：入口要求显式 `centerline` 或 `centerlineResolver`；类内禁止 `getCenterlinePoints()`。

ADR 0004 **仍不 enforce 分叉**（只 warning）——这是已记录产品决策，不是回归。

### P0 — 落地几何可能自相矛盾

**当前无开放 P0 项。** 原 P0-1（边走 HA 采样、路口读 `centerlinePoints`）已修复，见上文「已修复」与 Generation 几何原则。

---

### P1 — 正确性 / 失败语义 / 跨插件

#### P1-1 认领「全部失败」仍可能留下已写入边，且不跑修复

**位置**：`RoadNetworkManager.adoptSelectedPaths`、`RoadNetworkBuilder.adoptShape`

`adoptShape` 在 `createEdge` 之后才 `detectAndSplitIntersections`。求交中途抛错时 `adoptedCount` 不加，但边已进 live 网络。全组失败则直接 `return`，**跳过** `repairAfterAdopt`。

历史已 `pushHistory`，undo 能救，但失败文案不会提示「请撤销」；用户若随手保存，脏拓扑进 sidecar。

**建议**：任一组失败且 `adoptedCount == 0` 时 `history.undo`；或 `adoptShape` 做成失败全回滚。单测：`createEdge` 后强制抛错，断言网络回到认领前。

#### ~~P1-2 单边生成吞掉所有异常，当成功空结果~~（已修复）

原问题：`catch (Exception)` → 空 `RoadGenerationResult(0)`，与真正成功但 0 方块不可区分；失败边连接的路口仍生成 →「路口在、路没了」。

现行为（fail-soft，非整片 abort）：

```
EdgeGenerationOutcome: SUCCESS | SKIPPED | FAILED
NetworkGenerationResult: failedEdgeIds / warnings / errors / skippedJunctionIds
18/20 边成功 → 预览 WARNING「部分失败」；连接 FAILED 边的 junction 跳过
```

#### P1-3 预览/生成会静默改 live 派生几何（无 undo）

**位置**：`RoadNetworkGenerator.generateAll` → `DerivedCenterlineSynchronizer.synchronizeAll(network, …)`

计算预览即可 `setCenterlinePoints`；注释写明不写入撤销历史。随后工程保存会把派生折线写进 JSON。（P0-1 已修复：路口不再读 stale 折线；物化失败时边与路口仍可能不一致于 **persisted** 派生折线，但生成路径均走 `RoadPlanGeometry`。）

**建议**：对 `RoadNetwork.snapshot()` 生成；成功后再可选写回，写回必须 `pushHistory`。

#### ~~P1-4 土方设计标高：无 VA / 无手动节点标高 → 默认海平面~~（已修复）

原问题：`resolveNodeElevation` 无手动标高时返回 `TerrainSampler.DEFAULT_SEA_LEVEL`（64），土方误把「无设计纵断面」当成「设计标高 = 64」。

现行为：

- 有 active `DesignElevationSource`（MANUAL_PROFILE 等）→ 按纵断面采样
- 否则两端节点均有 `manualElevation` → 线性插值
- 否则 → `null`（不猜测）

土方 UI：道路走廊分区显示 `plugin.earthwork.no_road_design_elevation`；「记下道路高度」失败时同样提示。

**长期（仍开放）**：AUTO_SMOOTH 生成剖面缓存为 `ResolvedRoadDesignProfile` 供土方读取，而非重新猜或依赖一次性生成结果。

#### P1-5 生成器初始化失败被吞掉，插件半残启用

**位置**：`RoadSystemPlugin.onEnable`

```76:81:src/main/java/com/plot/plugin/RoadSystemPlugin.java
        try {
            RoadGenerator roadGenerator = new RoadGenerator(...);
            previewManager.setNetworkGenerator(new RoadNetworkGenerator(roadGenerator));
        } catch (Exception e) {
            LOGGER.error("初始化道路生成器失败: {}", e.getMessage(), e);
        }
```

土方 / 建筑在同等失败时会 `throw`。道路会继续启用，预览报「世界不可用」——文案误导。

**建议**：与另两个插件对齐，初始化失败即禁用。

#### P1-6 生成前硬门槛过窄

`analyzePreGeneration` 只有：过短 VA、FLAT 路口冲突。全量 `analyze()` 才有求交 incomplete（ERROR）、HA / 拓扑（WARNING）。`calculateNetworkPreview` / `buildRoadInWorld` 只用 preflight。

未打断交叉、HA 双轨、分叉路仍可出预览。

**建议**：把 `intersections_incomplete`、HA length / junction conflict 纳入 preflight。

#### P1-7 其它正确性

| 项 | 位置 | 说明 |
|----|------|------|
| 管线双重采样 | Orchestrator `samplePath` 后 Pipeline 再 `RoadGeometrySampler.sample`，按下标 `min(len)` 对齐高程 | 今日参数相同一般一致；一旦不确定，后段 silently 丢掉高程 |
| `mergeThroughNode` 失败回滚丢节点 | `RoadGraphEdits` 先 detach / removeNode，`createEdge` 失败再 restore | 当前帧网络已坏；undo 可救 |
| 中心线/物化失败仍 `pushHistory` | `filletVertex` / `materializeHorizontalAlignment` 等 | 一次无效 undo，且清预览 |
| 实体图元上限 10 万 | `RoadSolidModel.MAX_DEDUP_KEYS` | 超限静默丢块，UI 只 append warning |
| VA 端点可被路网共识盖掉 | `VerticalAlignmentProfileSolver` 用邻边自然高程覆盖 PVI | MANUAL_PROFILE 路口处设计被拉平 |

## 值得保留

1. **三层几何 + `RoadPlanGeometry` / `RoadGeometryAuthority`**，桩号 `canonical / design / instance` 分离。
2. **`OrientedRoadSegment` + `chainLeftNormal`**：反向边不镜像 LEFT/RIGHT。
3. **认领分组不合并 Y 形 + `repairAfterAdopt`**，与 ADR 0004 / 0005 一致。
4. **物化两阶段 + 路口 snap / 拒绝**；`CenterlinePhase2ConsistencyPolicy` 统一 split / merge / fillet。
5. **插件入口瘦**：`RoadSystemPlugin` 只装配；生成 façade `RoadGenerator`。
6. **持久化**：formatVersion、v0→v1 migration、原子写、fingerprint、损坏文件专用异常。
7. **预览 ≠ 落地**，落地走 `GenerateRoadCommand`，部分写入可 undo。
8. **工程检查目录 + drill-down**（`RoadValidationMessageCatalog`）。
9. **立体交叉**：节点标记 + `GradeSeparationPolicy`，人工 `elevatedRoadId` 优先。
10. **测试资产**：golden / orientation / topology splitter / HA 物化冲突。

## 与土方 / 建筑的耦合

- **建筑**：`com.plot.plugin.road` 无 building import。建筑经土方 `BuildingPadElevationService` 取垫层，不直接读路网。保持。
- **土方**：强耦合且契约已部分收紧（P1-4：无设计标高 → `null`）。走廊 / 中心线已走 `RoadPlanGeometry`（好）。`RoadSystemPlugin` 上的土方面向方法是插件边界泄漏（P2-4）。长期仍缺 AUTO_SMOOTH 剖面缓存。
