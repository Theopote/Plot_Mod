|----|------|------|

交叉口：

| 类型 | 注册 | 节点元数据 | 生成意图 |
|------|------|------------|----------|
| 两路平交 | `RoadCrossing` `AT_GRADE` | 共识 `junctionY` | 路口铺面 |
| 两路立交 | `GRADE_SEPARATED` | `isGradeSeparated` + 上跨路 + 净高 | 下穿铺面；上跨走廊 |
| 自交平交 | `RoadStackCrossing` 默认 `AT_GRADE` | 四臂 | 与十字平交相同 |
| 自交立交 | `GRADE_SEPARATED` | `isStackGradeSeparated` + 上下臂 | 下穿铺面；上臂走廊抬升 |

检测器在两条设计纵断面于交点处高差 ≥ 默认净空（3）时写出 `GRADE_SEPARATED`。物化失败不再静默 `COMPLETE`：`hasPartialFailure` 含 `crossingMaterializationFailures`。

可变横断面：

| 模式 | 解析 | 生成 | 画布叠加 |
|------|------|------|----------|
| 无变量 | 道路默认 `RoadCrossSection` | 固定 | 首段半宽 |
| `STEP` | 不大于桩号的最近断面 | 按桩号阶梯 | 仍用首段半宽 |
| `SMOOTH` | 相邻桩号宽度等连续量线性插值 | `ResolvedCrossSection.lerpContinuous` | 仍用首段半宽 |

## 仍存在的问题

### P0

无。建造主按钮与确认弹窗仍同时看 `isBuildPreviewCurrent`、`hasPartialFailure`（含交叉口物化失败）、校验 `blocksBuild`。

### P1

#### P1-1 可变横断面已进体素，画布走廊仍是首段恒定半宽 — **已关（本轮）**

`RoadOverlayGeometry.resolveRoadCorridorGeometry` 在存在可变断面时改走 `resolveVariableRoadCorridorGeometry`：按 `RoadPlanGeometry` 采样 + 断面桩号插入点，逐顶点 `VariableCrossSectionResolver.resolve` 半宽，经 `RoadCorridorGeometryBuilder.build(centerline, halfWidths, …)` 生成阶梯/平滑走廊。迷你预览改用道路中点桩号解析断面。

无变量道路仍走原等距半宽路径。命中/选区随走廊多边形变宽。

#### P1-2 用户向导仍按旧三 Tab 写 — **已关（本轮）**

`docs/zh|en/08-plugins.md` 道路节已改为：路径=认领/列表/交叉；编辑=预设+专业浮动窗；生成=纵向+预览+建造；并写明脏草稿挡切 Tab、可变宽走廊。

#### P1-3 脏浮动窗挡不住切 Tab / 换路 — **已关（本轮）**

`requestTab` 只写 `pendingTab`，不再立刻改 `activeTab`。`RoadUIManager` 离开 EDIT 前调 `editPanel.tryLeaveEdit()`；挡住则清 pending、强制下一帧 `SetSelected` 回 EDIT。换路走 `reconcileRoadScope`：`finishOrPromptOutsideScope` 挡住则回滚选择。隧道窗纳入同一离开/换路守卫（仍不在 Host 版本冲突重载里）。纵断面窗仍独立（GENERATE）。

证据：`RoadEditScopeGuardTest`、`RoadFloatingEditorHostTest`、`TunnelStyleFloatingEditorTest.dirtyFinishOrPromptBlocksLeaving`。

### P2

#### P2-1 交叉口编辑入口四处重复 — **已关（本轮）**

完整编辑只留 **PATH**（列表 + 详情 + 圆角/标线）与 **属性侧栏**。EDIT 已去掉顶上嵌套路口编辑器。GENERATE 只保留冲突摘要 + 提示 +「前往交叉关系」跳转，不再嵌套详情/列表编辑。

#### P2-2 浮动窗叠在同一中心、同一固定尺寸 — **已关（本轮）**

专业窗 / 隧道 / 预设库 / 纵断面打开时按 cascade 序号错开。专业窗与预设库仍固定 42%×48%、`NoResize`；纵断面走 `prepareResizableWindow`（默认 60%、可缩放 40%–90%），与专业窗共用 `RoadFloatingEditorShell` 错开与 flags 基座。诊断窗只读壳：仅「关闭」。

#### P2-3 「铁路」预设是道路皮肤，不是铁轨 — **命名 + 真轨轻量已关（本轮）**

展示名「铁路路基」/「Railway embankment」；`railway()` 现用 `CenterLineStyle.RAIL` + `minecraft:rail`，标线层落在路面上方一格。不含轨枕排布与道岔。

#### P2-4 平面线形（HA）与实例折线双轨 — **表述修正 / 生成已自动同步**

生成与叠加层中心线已统一走 `RoadPlanGeometry`：有有效 HA 时以设计线形为权威采样，**不必**先手动物化才进体素。预览/生成前 `DerivedCenterlineSynchronizer` 会写回实例折线；中心线浮动窗仍显示偏差并提供手动物化。

剩余缺口（产品增强，非阻塞）：采样折线间距（默认约 2 m）、画布上是否画缓和曲线示意。

#### P2-5 死 API：`canvasPreviewHalfWidthBlocks` — **已关（本轮）**

已从 `RoadCorridorWidth` 与测试删除。

#### P2-6 叠加层边坡开关只在路径头 — **已关（本轮）**

勾选框迁到公共顶栏 `RoadToolbarPanel`（三 Tab 可见）；路径头只留走廊显示开关。

#### P2-7 多选工具面过窄 — **已关（本轮）**

单路六卡（含隧道），列数按宽度在 2–3 间自适应。多选四卡：批量横断面 / 隧道 / 变截面 / 桩号设施（确认写入全部选中路）；中心线与诊断仍需单选。

#### P2-8 生成页仍然很长 — **部分关闭（本轮）**

主路径仍是状态 → 范围 → hint → 生成设置 → 预览/BUILD。纵断面概览与交叉检查改为默认折叠；全网统一标高保持折叠头。预览详情仍折叠。

#### P2-9 路径/编辑顶栏撤销仍全宽 — **已关（本轮）**

三 Tab 路网撤销/重做统一紧凑宽度（96–168）；世界撤销亦收窄。

| 表面 | 实际职责 | 不合适处 |
|------|----------|----------|
| **路径** | 拾取、走廊叠加开关、路网统计、总览图、道路列表、交叉口完整编辑（主场） | — |
| **编辑** | 单路：概览条、诊断横幅、迷你横断面、紧凑预设、宽/车道、六张工具卡（含隧道）。无选中：下拉选路 + 折叠默认。多选：批量预设/快调 + 批量横断面 | 多选仍无批量隧道/设施/变截面 |
| **生成** | 预览状态、范围、纵向策略、坡度/地形/纵断面来源、桥梁开关、计算/清除、摘要 + BUILD；纵断面/交叉/统一标高折叠 | — |
| **浮动专业窗** | 横断面、可变断面、中心线、设施、诊断、批量横断面；脏草稿/版本冲突确认 | 同尺寸；已错开默认位置；诊断只读关闭 |
| **预设库窗** | 点选即写回并关闭 | 点选立即 mutate，无草稿确认；与专业窗确认模型不一致 |
| **隧道浮动窗** | 全局默认或单路覆盖草稿 | 不在 Host 里，无版本冲突重载 |
| **纵断面窗** | 绿线、PVI、交叉标记、确认后重算预览 | 可缩放；与专业窗共用 cascade 壳 |
| **属性侧栏** | 交叉关系、平交标高、圆角/标线 | 与路径并列的交叉口入口 |
| **顶栏** | 路网撤销（紧凑）、边坡外缘叠加开关、世界撤销、预览进度 | — |

校验一键修复 `RoadValidationMessageUi` 仍在。生成确认弹窗与主按钮都看 `isBuildPreviewCurrent` 和 `hasPartialFailure`。

### UI 设计判断

三 Tab 职责现在清楚，编辑页「概览 + 快调 + 专业工具启动器」也对齐土方/建筑的工作区思路。问题不在信息架构，在窗口管理和重复入口：

1. **主路径干净，深工具靠浮动窗** — 方向对。
2. **窗已错开** — 专业工具固定尺寸；纵断面可缩放；共用 cascade。页脚模型仍分设计器 / 只读 / 纵断面三套。
3. **交叉口主场在路径** — 生成只检查并跳转；属性侧栏仍可改选中路口。
4. **看见的几何** — 可变宽走廊已跟桩号；边坡外缘默认关（顶栏可开）；HA 以采样折线进生成。
5. **铁路真轨** — 路基预设已铺中心 `minecraft:rail`；轨枕/道岔仍无。
