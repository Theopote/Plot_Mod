## P0

### 立交落地把上跨路拉向下穿标高

**现象**：隧道口或立交附近，上跨路面标高掉下来，和纵断面预览对不齐。

**机制**：

1. `NetworkNodeElevationResolver` 注释写明：立交节点存的是 **下穿层**。
2. `ProfileEndpointHeightResolver` 在求解时对上跨路走 `resolveForcedEndpointHeight`，得到下穿 + 净空。这一步是对的。
3. `RoadEdgeBuildOrchestrator.resolveEndpointSnaps` 把 **同一份** `networkNodeElevations` 交给 `EndpointElevationSnapResolver`。
4. 每个路面/边坡/隧道采样都调用 `host.snapEndpointElevation(center, targetY)` → `EndpointElevationBlender.blend`。混合半径是 `max(半宽+2, 默认路口半径)`。
5. 上跨路在路口附近的 `targetY` 被线性拉向节点上的下穿 Y。

`EndpointElevationBlenderTest` 只断言「在半径内混向 snap 高程」，没有立交上跨/下穿分轨用例。`RoadJunctionGenerator` 用节点标高铺路口面是合理的；错在 **边生成阶段把下穿标高再 snap 回上跨路**。

**建议**：snap 用「本边端点建造高程」（与 `ProfileEndpointHeightResolver.resolve` 同一值），不要直接用节点下穿层。立交节点对上跨路应禁用混向，或给上跨单独的 snap 高程。

## P1

### 1. 挖方包络不含边坡，桥隧整段不挖

`RoadCorridorWidth.gradingEnvelopeWidthBlocks` = 行车道 + `outerBandBlockCount()*2`，**不含** `includeSlopeBatter` 外扩。植被清理宽度 `decorationClearWidthBlocks` 才加上边坡裕量。

结果：路面底下的土会挖，边坡占位里的土只靠 `placeSlopeBatterAtPoint` 的空气柱。边坡一旦漏采样，原地块留下。

`RoadTerrainGrader.gradeRoadEnvelope` 在 `BRIDGE` / `TUNNEL` 上 `continue`，整段不做 `gradeCrossSectionEnvelope`。隧道腔体改由 `TunnelStructureGenerator` 挖；分类抖动或洞门过渡段既不是 TUNNEL 也没走明挖时，洞口岩石会留下。桥梁跳过挖填是为了留空，但浅桥（`targetY - ground ≤ bridgeThreshold` 才铺桥面板）可能让地面穿过桥面。

挖填沿路是 `j = 0..samples` 的点列，**没有** 路面那种 `addSpan`。斜向路两列世界方块之间会漏挖。

**建议**：

- 挖填包络与边坡外缘对齐（或至少用 `decorationClearWidthBlocks`）。
- 相邻采样点对空气柱做 span / 按世界列扫描。
- 桥隧只跳过结构净空内部，洞门/桥台过渡仍做明挖或边坡。

### 2. 边坡每段丢掉首尾，外扩硬顶 16 格

`RoadCrossSectionBuilder.generateSlopeBatterBlocks`：

```text
if (BRIDGE || TUNNEL) skip 整段
samples = max(2, ceil(distance / scale))
for j = 1; j < samples; j++   // 不含 0 和 samples
```

相邻两段的共享顶点两边都不画边坡，折线越碎空洞越多。整条路的起终点也没有边坡。

`placeSlopeBatterAtPoint` 里 `maxHorizontalRun = 16`，`RoadCorridorWidth.slopeBatterMarginBlocks` 同样 clamp 到 16。深路堑（例如高差 12、坡比 1.5）水平需要约 20 格，边坡在半截截断，看起来「缺一块」。

城市预设默认 `includeSlopeBatter = null/false`；高速/山路/乡道才为 true。未开边坡的城市路只靠包络竖切，两侧立陡坎。

**建议**：采样改为 `j = 0..samples`（与挖填、路面一致）；桥隧过渡单独补边坡；外扩按实际高差计算，去掉或提高 16 格顶。

### 3. 体素落格粗糙

| 来源 | 行为 |
|------|------|
| `WorldCoordinateUtils.canvasToBlockXZ` | `Math.round` 逐点，斜向呈锯齿，没有 6-连通补缝 |
| `RoadSolidPrimitive.dedupKey` | `layer + 浮点 x,y + elevation`，同一世界格可对应多个蓝图点；先写入者赢 |
| 落地 | 非隧道 `recordPlacementIfAbsent`，隧道层后写覆盖。漏掉的格不会被后写的空气补上 |
| 纵坡 | `VoxelElevationDiscretizer` / `BuildHeightProfile` 每 station 一格整数 Y，缓坡变台阶 |
| `RoadSolidModel.MAX_DEDUP_KEYS = 100000` | 长大路 + 边坡列先丢后续方块，表现为半截没了 |

路面有 `addSpan` 补纵向缝；挖填、边坡、隧道 mask 没有。

**建议**：去重键改为世界 `BlockPos`（或 round 后的格）；斜向用与电力线路类似的对称落格 + 列扫描；超限应失败/分块，不要静默丢块。

### 4. 附着物清理覆盖不到「非自然树」的柱体

`EngineeringTerrainService.sampleGroundSurface` 跳过空气/流体/自然附着物，地面 Y 在土石顶。  
`clearRoadDecorations` 只清 `groundY+1 .. topY` 且 `isRoadClearableDecoration`：草花、树叶、以及 `NaturalTreeClassifier` 认作自然树的原木。

分类失败的原木柱、玩家放的木梁、非 replaceable 的灌木会留在路面上方。`cutColumn` 只清到 `groundY`，清不到地面以上的非附着物。

**建议**：包络内 `groundY+1 .. columnTopY` 凡非路面保留块一律写成空气（或扩大 clearable 集合），不要只依赖自然树分类。

### 5. 构造分类最短 3 格，洞门/桥头易抖

`RoadConstructionHeuristics.MIN_STRUCTURE_RUN = 3`。短隧道被改写成 `CUT`（`RoadConstructionClassifier.validateTunnelSegment` 失败同样改 CUT）。分类在段级，一段内目标/地面高差变化时整段同一类型。洞门前后几格：边坡跳过、挖填跳过、隧道 mask 还没开始，岩石和路面标高对不齐。
