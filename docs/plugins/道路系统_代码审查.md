## 仍开放的 P1

### 1. 挖填包络仍不含边坡外缘

`RoadCorridorWidth.gradingEnvelopeWidthBlocks` = 行车道 + `outerBandBlockCount()*2`，**不含** `includeSlopeBatter`。植被清理 `decorationClearWidthBlocks` 才加上边坡裕量。

结果：硬质路面底下的土会挖干净；边坡占位里的原地形只靠 `placeSlopeBatterAtPoint` 写成坡面或空气。边坡一旦漏采样（见下条），原地块留下，看起来像「该挖的没挖完」。

**建议**：挖填包络与边坡外缘对齐，或至少对 `includeSlopeBatter` 路用 `decorationClearWidthBlocks`。

### 2. 边坡仍是逐点采样，没有站间 span

路面有 `solids.addSpan`；挖填有 `gradeSpanBetweenStations`。`generateSlopeBatterBlocks` 仍对每个 `j` 单独 `placeSlopeBatterAtPoint`，相邻桩号之间的斜向世界列不会补缝。

另外，`RoadTerrainGrader` 在 `TUNNEL_PORTAL` 上故意把 `previousCenter` 置空，洞门段 **不做** 站间 span（避免挖进洞身）。斜向洞口沿路仍可能漏一列。

**建议**：边坡相邻采样点按世界列 span；洞门段在本段内部 span，不要跨进 `TUNNEL` 内部。

### 3. 斜向补缝走画布整数格，不是世界格

`sampleConnectedPlanPoints`：

```text
x = round(left.x)   // 画布
z = round(left.y)
```

1:1 时画布格 = 世界格。`canvasUnitsPerBlock ≠ 1`（远景缩放、非 Identity 变换）时，画布 `0→1` 只走 2 个点，世界可能跨 4 格，中间漏。路口多边形已经改成世界格扫描，路面/挖填 span 还没有。

去重已经按 `BlockPos`，漏掉的格根本不会进蓝图。

**建议**：span 按 `canvasToBlockXZ` 后的世界列做 4-连通（与路口 `collectWorldCellPlanPoints` 同一套投影）。

## 已知产品锁（不改）

`RoadTerrainSemanticsTest.playerLogColumnPreservedWhenProductionSamplerReturnsFalse`：`NaturalTreeClassifier` 判否的原木柱（玩家木梁等）**不得**当附着物清掉。包络内非自然树的柱体仍会留在路面上方。扩大 clearable 集合会打破这条锁。

## 生成以外仍开放（不在本轮改动内）

此前纵断面编辑器审查仍未做：

- `VerticalProfileControlPoints.isEditablePvi` 锁死端点，双 PVI 路不能在独立窗口改高程
- PVI draft 只按 `roadId` 键、每帧写回，和生成页数字列表抢同一份 alignment
- 窗口标题即 ImGui ID，切边会丢位置/滚动
- 中途关窗会留下未提交的 undo 快照

预设卡片预览：`colorForMaterial` 把各种 `*_concrete` 收成浅灰；卡片用当前主题而不是各风格自己的 `themeId`。

## 建议下一刀（按收益）

1. **挖填包络包含边坡外缘**，边坡相邻桩号做世界列 span；洞门段只在本段内部 span。  
2. **span 改世界格 4-连通**（与路口扫描同一投影），去掉画布整数假设。  
3. **浅桥贴地也铺一层结构板**，或成本桥在贴地时改回 FILL，避免「断头填方」。  
4. 城市预设若要在地形里用，给一个非零坡比或显式 `includeSlopeBatter`。

玩家原木柱清障保持产品锁。
