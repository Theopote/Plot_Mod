# 道路系统插件 · 代码审查

> **日期**：2026-10-30  
> **范围**：`com.plot.plugin.RoadSystemPlugin`、`com.plot.plugin.road.*`、`RoadSystemConfig`、对应测试、`docs/zh|en/08-plugins.md`  
> **对照**：取代 2026-10-23 审查全文；2026-10-16 [交叉口与纵断面审查](道路系统_交叉口与纵断面_代码审查.md) 仍作历史对照，不再当作当前结论。  
> **本轮**：用户近期对道路插件做了大改（浮动专业编辑器、可变横断面 STEP/SMOOTH、铁路预设、交叉口物化失败上报、叠加层边坡开关、纵向控件迁 GENERATE、隧道/地形迁 EDIT）。只读审查，不改生产代码。

## 一句话

三 Tab 已经能讲清「路在哪 / 路长什么样 / 怎么落到世界」。快照预览、过期建造守卫、走廊管线、自动立交、浮动窗脏草稿确认都还在。当前没有挡住「能生成」的 P0。真正还差的是：可变宽在画布上看不见、向导仍按旧 Tab 写、交叉口入口重复、浮动窗叠在同一位置，以及名为「铁路」的预设其实是道路皮肤。

## 仍存在的问题

### P0

无。建造主按钮与确认弹窗仍同时看 `isBuildPreviewCurrent`、`hasPartialFailure`（含交叉口物化失败）、校验 `blocksBuild`。

### P1

#### P1-1 可变横断面已进体素，画布走廊仍是首段恒定半宽

生成侧 `CrossSectionBuildContext.resolve(chainage)` → `VariableCrossSectionResolver`，走廊计划按桩号变宽。画布侧 `RoadOverlayGeometry.resolveRoadHalfWidth` 取第一条边的断面后立刻 `return`，走廊多边形恒宽。

编辑页迷你预览 `RoadCrossSectionPreviewSection.renderSingle` 也只读 `road.getCrossSection()`，不反映桩号断面。

用户在可变断面编辑器里把路收窄/放宽，画布选区与命中盒仍按起点宽度。生成对了、看见的是错的。

#### P1-2 用户向导仍按旧三 Tab 写

`docs/zh/08-plugins.md`、`docs/en/08-plugins.md`：

- 路径仍写「纵向方式（适应地形 / 平路）与 Flat Base Y」
- 编辑仍写「预设、路宽、横断面、材质与附属设施」像内联表单
- 生成仍写「地形适应与最大坡度」为主，未提纵向策略已在此页

实际：纵向在 GENERATE；EDIT 是概览条 + 紧凑预设 + 快速宽/车道 + 五张专业工具卡 + 隧道覆盖；横断面/可变断面/中心线/设施/诊断全是浮动窗。

#### P1-3 脏浮动窗挡不住切 Tab / 换路

`RoadFloatingEditorHost.finishOrPromptAll` 注明「应阻止作用域切换」，返回 `blocked`。`RoadUIManager` 在 Tab 已经切走之后才调 `editPanel.finishPendingEdits()`，返回值丢掉。选择变化走 `finishOrPromptOutsideScope`，同样不回滚选择。

结果：确认弹窗出现时，主界面可能已经在另一条路或 GENERATE。继续编辑会看到「窗绑 A、列表选 B」。隧道窗、预设库、纵断面窗不走这套 Host，脏状态各自为政。

### P2

#### P2-1 交叉口编辑入口四处重复

同一套 `RoadIntersectionDetailPanel` + 立交控件出现在：

- PATH：列表 + 选中详情 + 圆角/标线
- EDIT：选中路口时顶上再画一遍
- GENERATE：交叉检查 + 可折叠详情 +「去路径 Tab」按钮
- 属性侧栏：`RoadNodePropertyPanel` 再画一遍

生成页还有「去路径看交叉口」，路径自己也能改。四处都能改立交，没有单一主入口。

#### P2-2 浮动窗叠在同一中心、同一固定尺寸

专业设计器壳 `RoadFloatingEditorShell`：屏宽 42% × 屏高 48%，`NoResize`，打开时居中。预设库复用同一尺寸。隧道窗复用同一 flags。用户连开横断面 + 可变断面 + 中心线，三窗完全重叠，只能拖开。

纵断面窗仍是另一套：默认屏宽 60%、可缩放 40%–90%、无 `NoResize`。最常用的高程工具和专业工具不像同一产品。

诊断窗是只读（`applySessionToLive` 空、session dirty 恒假），却套了「还原 / 取消 / 确认」页脚。

#### P2-3 「铁路」预设是道路皮肤，不是铁轨

`RoadStyleCatalog.railway()`：5 格抛光安山岩行车道、深板岩路肩、边坡、中线 `DOUBLE_SOLID` 铁块标线。没有 `minecraft:rail`、轨枕、道岔。i18n 名称是「铁路」/「Railway」。玩家按名字选，得到的是铁路路基风格的公路。

#### P2-4 平面线形（HA）不进体素采样

`RoadHorizontalAlignment` 有完整几何、一致性检查、物化到中心线。体素管线 `RoadGeometrySampler.sample(pathPoints)` 只吃边折线。HA 出现在 `ProfileCompileInputsFingerprint`（缓存失效）和中心线浮动窗摘要。缓和曲线/圆曲线只有物化回折线之后才进入生成。两套几何权威并存。

#### P2-5 死 API：`canvasPreviewHalfWidthBlocks`

生产叠加层已改用路面半宽。该方法仍留在 `RoadCorridorWidth`，只有 `RoadCorridorWidthTest` 调用。旧 P2-7 的生产缺口关了，API 没收拾。

#### P2-6 叠加层边坡开关只在路径头

`showSlopeBatterOverlay` 是全局 `ImBoolean`，勾选框只在 `RoadPathHeader`。EDIT / GENERATE 看不到、改不了。默认关闭，城市无边坡时外环本来就不会画。

#### P2-7 多选工具面过窄

多选只留「批量横断面」一张主按钮（刻意不渲染单路灰锁卡）。不能批量改隧道、设施、可变断面、中心线。`coming_soon` 文案和 Host 空类型回退还在，当前五张单路卡却全是 enabled，2×3 网格注释与五卡实际对不齐，末行单卡。

#### P2-8 生成页仍然很长

状态 → 范围 → 流程 hint → 生成设置（纵向/坡度/桥梁）→ 预览按钮 → 摘要 + BUILD → 纵断面工作区 → 交叉检查（整表）→ 全网统一标高工具 → 折叠详情。交叉口与纵断面已经能在各自窗口改，生成页仍把检查表和工具铺开。

#### P2-9 路径/编辑顶栏撤销仍全宽

GENERATE 路网撤销是紧凑钮 + 分段标题；PATH / EDIT 仍半宽一对按钮占满行。2026-10-23 只收了生成页。

## UI 结构对照

| 表面 | 实际职责 | 不合适处 |
|------|----------|----------|
| **路径** | 拾取、走廊/边坡叠加开关、路网统计、总览图、道路列表、交叉口完整编辑 | 边坡开关只有这里；交叉口编辑与另外三处重复 |
| **编辑** | 单路：概览条、诊断横幅、迷你横断面、紧凑预设、宽/车道、五张工具卡、隧道覆盖。无选中：下拉选路 + 折叠默认。多选：批量预设/快调 + 批量横断面 | 选中路口时顶上再嵌交叉口编辑；迷你预览不跟可变断面；五卡网格缺第六格 |
| **生成** | 预览状态、范围、纵向策略、坡度/地形/纵断面来源、桥梁开关、计算/清除、摘要 + BUILD、纵断面概览、交叉检查、统一标高 | 流程 hint 正确但页太长；交叉口又编辑一遍 |
| **浮动专业窗** | 横断面、可变断面、中心线、设施、诊断、批量横断面；脏草稿/版本冲突确认 | 同尺寸居中叠开；诊断不该用设计器页脚 |
| **预设库窗** | 点选即写回并关闭 | 点选立即 mutate，无草稿确认；与专业窗确认模型不一致 |
| **隧道浮动窗** | 全局默认或单路覆盖草稿 | 不在 Host 里，无版本冲突重载 |
| **纵断面窗** | 绿线、PVI、交叉标记、确认后重算预览 | 尺寸/缩放与专业窗两套壳 |
| **属性侧栏** | 交叉关系、平交标高、圆角/标线 | 立交再画第四份 |
| **顶栏** | 路网撤销；有世界改动时世界撤销；预览进度 | PATH/EDIT 撤销全宽 |

校验一键修复 `RoadValidationMessageUi` 仍在。生成确认弹窗与主按钮都看 `isBuildPreviewCurrent` 和 `hasPartialFailure`。

### UI 设计判断

三 Tab 职责现在清楚，编辑页「概览 + 快调 + 专业工具启动器」也对齐土方/建筑的工作区思路。问题不在信息架构，在窗口管理和重复入口：

1. **主路径干净，深工具靠浮动窗** — 方向对。
2. **窗太多且出生点相同** — 专业工具、预设库、隧道、纵断面四套壳。专业窗还不能改大小。
3. **交叉口没有主场** — 路径适合管关系，生成适合检查冲突，编辑和属性侧栏再放完整编辑器会抢注意力。
4. **看见的几何落后于生成** — 可变宽、边坡外缘（默认关）、HA 曲线，画布都不画或画不全。
5. **「铁路」这个名字** — 卡片叫铁路，生成出来是公路横断面。

## 缺口（相对目标产品）

这些不是回归，是能力还没接到生成或画布上。

| 缺口 | 现状 | 影响 |
|------|------|------|
| 可变宽画布走廊 | 生成按桩号变宽，叠加层恒宽 | 选区/命中/总览与落地不一致 |
| 铁轨几何 | 铁路预设是路基皮肤 | 名字承诺的轨道、轨枕、道岔没有 |
| 平面线形驱动体素 | HA 可编辑、可物化；采样仍走折线 | 缓和曲线只有物化后才进世界 |
| 多选专业工具 | 只有批量横断面 | 多路改隧道/设施/变宽要逐条打开 |
| 复杂多路交叉口专业编辑 | `ComplexJunctionGuidePanel` 仍是说明 + 高级折叠 | 多路交叉没有独立设计器 |
| 向导 | zh/en `08-plugins.md` 停在纵向还在路径、横断面还在编辑页内联 | 按文档走会找不到控件 |

产品锁仍有效：玩家放置的原木柱，`NaturalTreeClassifier` 返回 false 时保留，不要扩成清所有原木。

## 建议处理顺序（先别改，等通知）

1. **P1-1** 画布走廊按桩号取断面半宽（至少 STEP 阶梯多边形；SMOOTH 可先分段线性）。迷你预览跟当前桩号或道路代表断面。
2. **P1-2** 重写 `docs/zh|en/08-plugins.md` 三 Tab 表：路径=认领/列表/交叉；编辑=预设+专业浮动窗；生成=纵向+预览+建造。
3. **P1-3** `finishOrPromptAll` / `finishOrPromptOutsideScope` 返回 true 时挡住切 Tab 和换路；隧道/纵断面纳入同一套脏确认，或至少不要在未确认时丢掉草稿。
4. **P2-1** 交叉口完整编辑只留 PATH + 属性侧栏；EDIT 去掉顶上嵌套；GENERATE 只保留冲突摘要和跳转。
5. **P2-2** 专业窗错开默认位置（或记住上次坐标）；诊断改为只读壳（无确认页脚）；纵断面与专业窗共用可缩放策略。
6. **P2-3** 铁路预设改名（「铁路路基」）或真正铺轨。
7. **P2-4 / P2-5 / P2-6 / P2-7 / P2-8 / P2-9** 按产品优先级：HA 物化后采样、删死 API、边坡开关提到公共顶栏、补齐六卡或改成自适应网格、生成页交叉表改折叠、PATH/EDIT 撤销改紧凑。

## 保持不动

- 三 Tab 主路径
- 预览必须 `network.snapshot()`，live 路网不进体素
- `isBuildPreviewCurrent` + `hasPartialFailure`（含交叉口物化失败）双门建造
- 走廊管线与 `SlopeEnvelopeClearancePass` 写在 `RoadCorridorPlanBuilder`
- `CrossingGradeClassifier` 自动立交阈值与 reconcile 保留用户类型
- 浮动专业窗工作副本 + 版本冲突重载（Host 内）
- 叠加层默认硬质路面、边坡外环可选
- 玩家原木柱清场策略
- 不把土方 / 电力 / 图案的 `getInstance()` 算进本插件
