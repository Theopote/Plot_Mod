# 土方平衡插件 · 代码审查

> **日期**：2026-09-07  
> **范围**：`com.plot.plugin.EarthworkPlugin`、`com.plot.plugin.earthwork.*`、`EarthworkConfig`、对应测试、ADR 0009、产品定位  
> **性质**：只读审查。历史报告仅作背景；下列问题均以当前代码核对。

## 一句话

土方已从「单区域整平」长成 **Site / Zone / 边坡 / 挡墙 / 道路走廊 / 建筑垫层** 的完整整形管线；2.0 拆分和 ADR 0009 的 Quick 主路径已经落地。真正卡住玩家的，是 **预览捕获经常采不到放坡带**，平衡数字在「无坡」网格上算完，和产品 P0（边坡后再算方量、Preview = Build = Report）对不上。

## 架构概览

```
EarthworkPlugin（~334 行）             生命周期 / sidecar 持久化 / 画布叠加
  ├ EarthworkPreviewManager            预览、虚影、报表导出
  ├ EarthworkBuildManager              落地（复用 lastGenerationResult）
  └ EarthworkUIManager
        QuickPanel  或  Overview / Adopt / Edit / Generate

EarthworkPipelines
  ├ LegacyRegionPipeline               单区、无主动边缘处理时委托
  └ SiteEarthworkPipeline
        Capture → DesignTerrainComposer → Volume/Voxel → RetainingWall

模型：EarthworkProject → EarthworkSite → GradingZone（包着 GradingRegion）
```

玩家主路径（产品定位）：框选 → 自动平衡 / 指定 Y → 垂直 / 自然坡 / 挡墙 → 预览 / 施工。Builder / Learn 才露出分区类型、合成策略、材料换算。

## 问题清单

### P0 — 玩家主路径会算错

#### P0-1 预览捕获不包含放坡带，边坡方量经常是 0

**位置**

- `EarthworkPreviewManager.calculatePreview`：`terrainCache.captureFreshSite(site, …)`
- `TerrainSnapshotCache.captureForSite`：只用 `site.getSiteBoundary()`（分区 AABB，**不含** `maximumReachBlocks`）
- `SiteEarthworkPipeline.execute`：先 `expandAxisAlignedBoundary(siteBoundary, edgeMargin)`，再 `SiteTerrainCapture.captureSite(..., context.terrainSnapshot())`
- `SiteTerrainCapture.captureSite`：快照非空则**原样返回**，不按扩大后的红线重采

```27:29:src/main/java/com/plot/plugin/earthwork/terrain/SiteTerrainCapture.java
        if (terrainSnapshot != null && !terrainSnapshot.isEmpty()) {
            return terrainSnapshot;
        }
```

`ZoneBoundarySlopeApplicator.applyExteriorSlopes` 只改**多边形外且已在 grid 里**的格。grid 来自 snapshot 列。玩家选 Quick「自然坡」后：

1. `delegatesToLegacyGenerator()` 因 `hasActiveTreatment()` 为 true → 走 site 管线（对）
2. 捕获仍是垫层 AABB（错）
3. 外侧坡格不存在 → 边坡不参与挖填
4. `SlopeCoupledVerticalSearch` 在「无坡」网格上选 Y，UI 仍显示 Balanced

合成器单测是对的：`DesignTerrainComposerTest.slopedSinglePadTerrain()` **手工塞了**外侧柱；`PhaseFEdgeTreatmentTest` 同样预置。**没有测试 PreviewManager / Capture 这条玩家入口。**

**为何是问题**：ADR 0009「每次候选 Y 必须含最终边坡后再算方量」在 UI 上不成立；自然坡 ≈ 垂直切削，平衡数字骗人。

**建议**

- `captureFreshSite` 用 `expandAxisAlignedBoundary(boundary, resolveEdgeSlopeMarginBlocks(...))`
- `SiteTerrainCapture`：快照覆盖不住请求边界就重采 / 补采
- 回归：自然坡断言外侧格存在且 `targetY` 在 toe 与 ground 之间

#### P0-2 标高—方量曲线用「整网平移」，不是边坡重建

**位置**：`EarthworkElevationVolumeCurve.volumeAt`：`designY = column.designY() + (candidateY - referenceY)`

Quick 折叠「查看分析」、Learn 的「挖填平衡 / 最少施工」两个推荐都吃它。产品 / ADR：**禁止**对已含坡的网格做一维平移当方量。合成器里 `SlopeCoupledVerticalSearch` 是对的（每个 ΔY `restoreCells` + 再 `applyBoundaryConditions`）。曲线是另一套近似。

有边坡时，曲线上的 `balanceY` / `minWorkY` 可以和真正推荐 Y 不一致。玩家按曲线改 slider，数字与最终地形会分叉。

**建议**：曲线每个整数 Y 复用 `UniformCandidateEvaluator`；至少在 `hasActiveTreatment()` 时禁用平移曲线。

### P1 — 主路径体验 / 双轨 / 联动

#### P1-1 双轨管线：Quick 垂直切削走 legacy，一开自然坡就换算法

**位置**：`EarthworkSite.delegatesToLegacyGenerator()`、`EarthworkPreviewManager.calculatePreview`

单区 + 无边缘处理 + 无 breakline / exclusion → 直接 `legacyPipeline.execute(...)`，**不**经 `SiteEarthworkPipeline`。Legacy 结果 **没有** `designTerrainGrid`。

- 垂直切削：legacy 用 `EarthworkBalanceUtils` 对垫层样本二分
- 自然坡：site 用 ±N 边坡耦合搜索

同一块地切换边缘，推荐 Y 与可视化能力跳变。Quick 热力图吃 `designTerrainGrid`，垂直切削时为 null。

**建议**：单区也固定走 `SiteEarthworkPipeline`；legacy 仅给旧 JSON / 测试。至少 legacy 也产出 `DesignTerrainGrid`。

#### P1-2 「计算预览」不清 3D 虚影以外的自动投影

`calculatePreview` 会 `clearAllGhostBlocks()`，成功后**不**调用 `projectPreview()`。虚影要再点「投影」。产品主流程是「看预览 → 微调 → 施工」。现在只有面板数字；世界里可能是空的。

施工同源 `placementRecords`（这块是对的），但玩家感知的 Preview ≠ 看见的地形。

**建议**：`calculatePreview` 成功后立刻 `projectPreview()`；slider 的 280 ms debounce 保持即可。

#### P1-3 默认自动平衡搜索半幅可达 ±32

`VerticalAdjustmentPolicy.defaultFor(FLAT, autoBalance=true)` → `adjustable(UNBOUNDED_RANGE=32)`。有自然坡时最多 **65 次** `restore + offset + blend + daylight`。Builder 滑条 `max_auto_adjust` 上限是 16，内部默认仍是 32。

**建议**：Minecraft 默认半幅用 `SlopeCoupledVerticalSearch.DEFAULT_HALF_RANGE`（3），或与 UI 的 16 对齐。

#### P1-4 道路走廊采样失败会静默铺成「场地平均地面」

`RoadCorridorSurfaceResolver.evaluateTargetY`：`roadEdgeRef` 空、`lookup == NONE`、或 `sampleDesignY == null` → `fallbackElevation`（全场地面平均）。走廊变成一块平均高度平台，和路床脱节且无硬错误。叠加道路侧 P1-4（无 VA 返回 64）。

`EarthworkValidator.analyzePrePreview` 在 `delegatesToLegacyGenerator()` 时直接 return，单区走廊可能跳过场地校验。

**建议**：`ROAD_CORRIDOR` 引用失败 = 阻断预览，不要用场地均值。

#### P1-5 多区报告把「全场 min/max Y」写进每个 Zone

`DefaultSiteEarthworkOperations.applyZoneLastReports`：每个 zone 的 `lastResolvedElevation*` 都赋全场值。垫层 64、基坑 40 时，分区上次标高全是场地均值。建筑若读 region 上次标高会错。

**建议**：按 `DesignTerrainGrid` 该 `zoneId` 的 min / max 回写。

#### P1-6 挡墙方块记成 FILL；虚影 stride 抽稀

- `RetainingWallGenerator.recordWallBlock`：`changeTypes.put(pos, FILL)`。确认框用 `totalChangedBlocks()`，挡墙会让填方改块膨胀。
- `projectPreview`：`total > 4000` 时 `stride = ceil(total/4000)`，施工仍用全量。大场地红蓝玻璃 ≠ 落地。

**建议**：墙用独立 `ChangeType`；抽稀时提示「预览已抽稀」。

#### P1-7 Builder 仍能打开「分区约束优化 / 项目级平衡范围」

`EarthworkEditPanel.renderBalanceMethodSettings`：多区即可选 `CONSTRAINED_ZONE_OPTIMIZATION`。ADR 0009 冻结 Mode B 自动改各 Zone 标高。Learn 才应露出。

#### P1-8 违反 ADR 0001：`PluginManager.getInstance()`

`EarthworkPlugin` 叠加层、`EarthworkUiLookups`、`EarthworkEditPanel` 用 `PluginManager.getInstance().getPlugin("building" | "road_system")` 再 instanceof。建筑侧对称调用土方。插件边界靠具体类，而不是注入的 lookup。

## 值得保留

1. **薄 Plugin + Manager + Pipeline**，对齐道路；`TerrainSnapshot` + `BlockSampler` 可无 World 测。
2. **`SlopeCoupledVerticalSearch` + `MAX_SITE_BALANCE_ITERATIONS` 重建坡面**：合成器侧算法方向正确（见 `DesignTerrainComposerTest`）。
3. **Preview / Build 共用 `placementRecords`**；施工前 `comparePreviewTerrainWithWorld`。
4. **几何方量 vs 世界改块** 分列；玩家控件走 geometric。
5. **建筑循环依赖切断**：`BuildingPadElevationService` 在 `BUILDING_BASE_ELEVATION` 时不把垫层 Y 回写给建筑。
6. **`RoadSurfaceLookup` / `BuildingFootprintLookup` 接口**干净。
7. **Schema 迁移 v1→v3** + 原子写；损坏 JSON 不静默变空项目。
8. **Quick 三选一边缘**（`EarthworkQuickEdge`）映射到底层 `EdgeTreatment` 的方式对。
9. **280 ms debounce**（`scheduleRecalculatePreview`）避免拖 slider 每帧跑完整管线。

## 改造建议

### 短期（先修玩家主路径）

1. 捕获扩大放坡带；快照与请求 bbox 不一致必须重采（P0-1）。测试走 Preview / Capture，不要只 compose 预置柱。
2. 有主动边坡时，曲线不要 `volumeAt` 平移（P0-2）。
3. `calculatePreview` 成功后自动 `projectPreview()`（P1-2）。
4. 单区默认 site 管线，保证 `designTerrainGrid` 始终有（P1-1）。
5. 搜索半幅默认 3 或 16，不要 32（P1-3）。
6. 道路走廊 fail-closed（P1-4）。

### 中期

1. Builder 去掉 `CONSTRAINED_ZONE_OPTIMIZATION` / `PROJECT` 范围；Mode B 只留 Learn。
2. 拆 `EarthworkEditPanel`：几何 / 边缘 / 联动各一块。
3. `GradingRegion` 降为纯几何 DTO，标高只活在 `DesignSurface`。
4. 挡墙变更类型与报表分离；虚影抽稀明示。
5. 跨插件 lookup 经 `PluginContext` 注入，去掉 `PluginManager.getInstance()`。
6. `EarthworkConfig` 删运行时方量；保存改 `AtomicFileWriter`。

## 关键调用链

玩家点预览：

```
EarthworkUiContext.recalculatePreview
  → EarthworkPreviewManager.calculatePreview
       ├ 单区无坡 → LegacyRegionPipeline.execute（无 designTerrainGrid）
       └ 有坡 / 多区 → captureFreshSite（未扩边）
            → SiteEarthworkPipeline.execute（扩边但被非空 snapshot 吞掉）
            → DesignTerrainComposer.compose
            → EarthworkVolumeCalculator.computeFromDesignGrid
            → EarthworkVoxelizer.applyColumn
```

施工：`EarthworkBuildManager.buildInWorld` 只消费 `lastGenerationResult.placementRecords`（同源，前提是预览网格本身完整）。
