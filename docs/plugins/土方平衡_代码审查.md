## 应保留

- 玩家主路径 `SiteEarthworkPipeline`：Capture → Compose → Volume/Voxel → 挡墙。
- 预览状态机 `NONE` / `VALID` / `DIRTY` / `CALCULATING` / `FAILED`；参数变更立即 `DIRTY`；计算令牌丢弃过期结果。
- 施工：`validateBuildEligibilityWithoutTerrain` 只给按钮启用；确认弹窗 / `buildInWorld` 强制 `validateBuildEligibilityFresh`。
- 建筑平台、道路走廊引用解析失败则预览失败，不静默用 64。
- Minecraft 1:1：主 UI 用 `geometricCutVolume` / `geometricFillVolume` 说话；材料换算留在底层。
- Quick 边缘三选一映射 `ZoneEdgeSettings`（垂直 / 自然 1:1 / 挡墙）。
- Quick 分析图表默认收起；画布挖填热力图在 Quick 关闭，避免和幽灵抢视觉。
- 工作模式切换不写回 `EarthworkSite` 高级合成参数。
- `EarthworkBalanceStatus` 把未运行 / 已平衡 / 尽力 / 约束限制 / 搜索失败分开，失败不得记成残余 0。
- `IBuildingPadElevationService`：土方主导的平台标高给建筑插件，垫层跟随建筑时返回 null，避免循环。
- 幽灵超过 4000 条抽稀，并提示简化。
- Slider 变更 280ms 防抖后重算，拖动时先 `DIRTY`。
- 测试：`com.plot.plugin.earthwork.*` 本轮 70 个套件、306 项，0 失败（2026-10-23）。

## P1

### P1-1 未加载列按 Y=64 参与挖填与推荐高度

`EngineeringTerrainService.sampleGroundSurface` 在区块未加载时返回 `DEFAULT_GROUND_ELEVATION = 64`。`TerrainSnapshot.capture` 会记下 `chunkLoaded=false`，但仍把这个 64 写成 `groundY`。

之后这条假地面进入整条主路径：

- `DesignTerrainCell` 只存 `existingGroundY`，没有 `chunkLoaded`。
- `EarthworkVolumeCalculator.toColumn` 用四参 `Column` 构造，默认 `chunkLoaded=true`。
- `EarthworkVoxelizer.applyColumn` 直接用 `column.groundY()` 算挖填并生成 placement。
- `TerrainSnapshot.compareWithCurrentWorld` **跳过** `!chunkLoaded` 的列，假 64 永远不会被标成地形变化。
- 因此 `validateBuildEligibilityFresh` 放行，Preview / Build / Report 对这批列彼此一致，相对真实地形不一致。

土方测试里没有 `chunkLoaded` 断言。道路侧同类问题已按「全程未加载不拿 64 做挖填」收敛；土方这边推荐高度本身就从这些列算出来，影响更大。

建议：未加载列不参与平衡目标、方量与体素；UI 提示未加载格数；过多时拒绝预览/落地（图案插件已有类似门禁）。

### P1-2 自动平衡是 ±8 / ±16 局部搜索，不是全整数 Y 扫描

产品写法：对候选整数 Y 完整生成含边坡再取最小 \|cut−fill\|，「即使 Y55–Y90 也只有几十次」。

代码：

- `SlopeCoupledVerticalSearch.DEFAULT_HALF_RANGE = 3`（7 档），作为搜索起点。
- `resolveUniformSearchHalfRange` 再取可调分区 `VerticalAdjustmentPolicy` 的 min/max，最后封顶 `QUICK_AUTO_BALANCE_RANGE=8` / `BUILDER_AUTO_BALANCE_RANGE=16`。
- 单区自动平整默认 `adjustable(8)`，所以 Quick 实际扫当前设计 Y 附近 ±8。
- 目标是相对当前设计面的 ΔY，不是从地形 min 扫到 max。

机制已经是边坡耦合离散搜索（满足「先放坡再比方量」），但高差超过 ±8 / ±16 的全局最优点进不了候选。`hitSearchBoundary` 会进 `BEST_EFFORT` 警告，玩家不一定懂这是搜索幅不够。

建议：Quick 在地形样本 `[minY, maxY]`（可再加少量边）上做边坡耦合全扫描；Builder 可用更大幅或保留当前封顶。曲线/推荐按钮应走同一套候选，而不是无边坡时的整网平移近似。

## P2

### P2-1 叠加层仍用 `PluginManager.getInstance().getActivePlugin()`

`EarthworkPlugin.renderEdgeTreatmentOverlay` 第 188 行用定位器判断是否当前插件。道路叠加已改为看 `PluginState.ACTIVE`。ADR 0001：插件经 `PluginContext` 访问宿主，禁止新增 `*.getInstance()`。

`this.getState() == PluginState.ACTIVE` 即可，不必再查 `PluginManager`。

### P2-2 跨插件查询走 `PluginManager.getInstance().getPlugin`

`EarthworkUiLookups`、`EarthworkEditPanel` 查 `building` / `road_system` 都直接 `PluginManager.getInstance()`。宿主还没有等价的 `PluginContext.plugins()`。这是已知定位器面，新增查询不要再铺开。

### P2-3 `EarthworkConfig` 用 `LogManager.getInstance()`

load/save IO 失败三条日志。与 ADR 0001 同类，改 SLF4J 即可。

### P2-4 拾取 Escape 走 ImGui，不走 `ShortcutManager`

`EarthworkRegionPickSession`、`EarthworkThreePointPickSession`：`ImGui.isKeyPressed(ImGuiKey.Escape)`。道路拾取已注册 `ctx().shortcuts()`。土方 Esc 在 ImGui 未聚焦或快捷键被占用时可能丢。

### P2-5 用户向导与默认 UI 不一致

`docs/zh/08-plugins.md` / `docs/en/08-plugins.md`：土方与建筑/图案一样写「区域 / 编辑 / 生成」三标签，流程第 3 步是区域页。实际默认 `QUICK`，单滚动页（认领、目标、边缘、预览、建造），三标签只在切到建造模式后出现。向导也没写 Quick / Builder。

产品文档仍写三种工作模式含 Learn；代码已把 Learn 并入 Builder。

### P2-6 Quick 边缘缺「缓坡」

产品 Quick：垂直 / 自然坡 / 缓坡 / 挡墙。`EarthworkQuickEdge` 只有 `VERTICAL` / `NATURAL`（1:1）/ `RETAINING`。缓坡没有独立档。

### P2-7 生成页「建造」在图表与导出之后

`EarthworkGeneratePanel.render`：预览操作（含「直接建造」会先重算）→ 网格 → 过期提示 → 方量/图表/工程报告/导出/警告 → `renderPreviewBuildButtons`。Quick 同样：预览操作 → 摘要 → 建造 → 收起的分析。

道路生成页已把摘要 + BUILD 提前。土方「直接建造」在顶部，缓存预览的「建造」仍在长内容后面。

### P2-8 有边坡时标高—方量曲线被关掉

`SiteEarthworkPipeline`：`attachPlayerInsights(!site.hasActiveSlopeTreatment())`。有自然坡时 `elevationVolumeCurveRequiresSlopeCoupledSolver=true`，Insight 只留一句提示，两个推荐高度按钮（挖填平衡 / 最少施工）也不出现。这正是产品 P2 可视化要讲的内容，也是 P1-2 全扫描的展示面。

### P2-9 Builder 编辑页仍暴露 LOCKED / DERIVED / BOUNDED

产品与 ADR 0009 冻结「VerticalAdjustmentPolicy 全家桶」，区域约束简化为 `autoAdjustElevation` + `maxAutoAdjustment`。`EarthworkEditPanel.renderVerticalAdjustmentPolicy` 在 `showsEngineeringMetrics()`（即 Builder）下仍列出四种 Mode 与 min/max/weight。底层保留策略是对的；主路径控件与冻结文案不一致。

### P2-10 空样本 / 缺控制点回退 64

与未加载列不同：没有地形样本或三点/坡锚缺失时，`EarthworkBalanceUtils`、`GradingSurfaceResolver`、`DesignSurfaceResolver`、Quick slider 种子、挡墙底标高会写 64。这是海平面占位，不是区块未加载。空场地应拒绝求解或明确提示，避免推荐 Y64 看起来像算出来的。

### P2-11 `EarthworkEditPanel` 约 1597 行

编辑 Tab 把合成策略、分区类型、竖向策略、设计面、几何、边坡、挡墙、建筑平台、基坑、道路导入堆在一个类。2.0 已把 Plugin 拆薄，下一个拆分点是这个面板。

### P2-12 插件工具栏只有方案撤销

`EarthworkToolbarPanel` 是 `EarthworkProjectHistory` undo/redo，成功落地会 `host.commands().pushExecuted`。面板内没有道路那种「世界落地撤销」。玩家要撤施工只能靠宿主命令栈。
