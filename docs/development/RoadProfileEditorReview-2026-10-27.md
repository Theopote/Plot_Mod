# 纵断面编辑与求解检查（2026-10-27）

本轮检查编辑草稿、窗口事务、道路切换、撤销恢复、交点传播、编辑曲线显示、方块线缓存及生成侧纵断面专项。以下八项已修复；并不表示游戏内所有交叉口、所有地形组合已完成实景验收。

## 已修复的问题

| 问题 | 原因及影响 | 修复 |
|---|---|---|
| 水平道路拖动预览不联动其他道路 | `ProfileEditSession` 为水平道路走专用预览，仅改当前路的平面，没有调用提交时的交点同步。松手前后显示不一致 | 临时快照与提交共用 `applyAndSynchronize`，保持工作路网、live 路网隔离 |
| 拖动立交另一层时，绿色曲线和交点标记仍显示旧高度 | 净空求解可能连带推高当前道路，但绘图读的是原工作路网或未求解的草稿；水平路 OTHER 拖动还误建了当前路的新水平草稿 | 渲染设计线、控制点和标记统一读取已经同步的临时路网；OTHER 拖动只编辑实际目标道路 |
| 锁定 PVI 仍能拖动 | 右键菜单禁用了锁定点输入，但控制点的 `elevationEditable` 没检查 USER_LOCKED，端点直接返回可编辑 | 统一控制点权限；会话数值和拖动入口也拒绝锁定点及非有限输入 |
| 右键高程框初值与编辑对象不同 | 初值读取 PVI 桩号处的曲面高程，提交却修改切线交点的控制标高；有圆滑曲线时两者不相等 | 数值框显示它实际编辑的 PVI 标高，与图中控制点一致；交叉点路面高程仍走交点专用编辑入口 |
| 等长路线变形仍复用旧方块线 | 预览指纹只含长度、边 ID 和端点；镜像后的内部折点、等长平面线形参数可不改变旧指纹 | 预览指纹加入完整中心线或水平线形内容、道路拓扑及立交上下角色。既有持久化编辑曲线签名格式不变 |
| 等待中的方块线计算没有被编辑/撤销取消 | `markStale` 忽略 COMPUTING；下个 UI tick 仍可能执行旧快照请求 | COMPUTING 也转为 STALE，现有执行入口会跳过失效请求 |
| 仅查看水平道路就出现“未保存” | 生成派生 alignment 时只更新工作副本，基线没有相同派生数据 | 仅当该道路尚无真实修改时，在基线独立生成相同派生曲线；不修改 live 路网 |
| 初始化交点锚点覆盖恢复基线 | 将工作副本中加锚点后的整条曲线复制进打开快照，可能把用户已编辑的高度当成初始状态 | 工作副本和基线各自从自己的原始曲线推导锚点，禁止复制用户编辑后的高程进入基线 |

## 验证

- 先用回归测试复现了预览联动、立交显示、锁定点及等长变形缓存四项失败，再修复。
- 两个窗口基线问题另行先复现失败，再修复。
- 最终 `profile.*`、`vertical.*`、`pipeline.profile.*` 专项共 486 项通过；包含撤销重做、编辑草稿、交叉点及自交、常规平滑、连续性和采样/方块线一致性等现有测试。
- 新增检查：等待中的计算被标记失效后不会继续处于 COMPUTING。
- 右键输入初值改动经过代码检查，未进行 ImGui 实机点击验证。

验证期间工作区有其他任务新增测试。`MixedCrossingElevationAuthorityTest` 引用了当时尚不存在的 `forGeneration` / `forDesignOverlay` 接口，导致正常的 `compileTestJava` 失败；本轮没有修改或删除该文件。专项使用位于 ignored `build/` 下的临时 Gradle init script，仅排除该文件编译，以上 486 项通过不能当作整个工作区集成构建全部通过。其他并行文件的修改保持原状。

## 仍需注意

- “更新方块线”虽然延后到下一帧执行，但计算仍同步运行在编辑器 tick 中，尚未成为真正可分帧的计算任务。长道路可能仍有停顿；本轮未做耗时基准，不能宣称性能问题已解决。读取 Minecraft 地形有线程约束，也不宜直接把整个任务移到后台线程。
- 保存曲线的持久化几何签名与方块预览指纹目前仍是不同兼容需求。本轮只扩充预览指纹，没有强制让用户已有确认曲线全部失效；若全面升级持久化签名，需配套旧工程迁移与等长几何改动回归。
- 未运行 Minecraft 实景验证；旧的路口净空和快照基线问题不属于本轮修复结论。
