# Plot 视频教程制作要点

## 录制前准备

### 技术准备

#### 软件与工具
- **录屏软件**：OBS Studio（推荐）或 Bandicam
  - 分辨率：1920x1080 或 2560x1440
  - 帧率：60 FPS（流畅操作演示）
  - 编码：H.264，码率 8000-12000 kbps
- **音频录制**：
  - 麦克风：建议使用电容麦或领夹麦
  - 降噪软件：Audacity 或 Adobe Audition
  - 背景音乐：免版权音乐库（YouTube Audio Library、Epidemic Sound）
- **视频编辑**：
  - Adobe Premiere Pro / DaVinci Resolve / 剪映专业版
  - 特效：适度使用，不要过度
- **字幕制作**：
  - 自动语音识别 + 人工校对
  - 中英双语字幕（上下分行或并排）

#### Minecraft 设置
- **游戏版本**：1.21.10 + Fabric Loader + Fabric API + Plot 模组
- **视频设置**：
  - 渲染距离：16-32 区块（根据场景调整）
  - 关闭视角抖动
  - 亮度调至明亮
  - 光影：可选（建议用于最终展示，录制教程时关闭以提高清晰度）
- **资源包**：使用清晰的材质包（推荐原版或简洁风格）
- **快捷键检查**：确保 Plot 快捷键不与其他模组冲突

#### Plot 配置
- **清理测试数据**：删除之前的测试图层和项目
- **重置设置**：使用默认配置，避免个性化设置干扰教学
- **准备素材**：
  - 示例项目文件
  - 预绘制的图形（某些章节）
  - 测试世界存档（平坦地形 + 特定地形）

## 录制技巧

### 视觉呈现

#### 画面构图
- **Plot 界面**：
  - 画布居中，工具栏和面板完整可见
  - 避免被游戏聊天框、调试信息遮挡（F1 隐藏 HUD）
  - 关键操作时适当放大工具栏或参数面板
- **游戏世界**：
  - 使用第三人称视角展示建造成果
  - 俯视角展示整体布局
  - 细节展示用第一人称近距离查看

#### 操作可见性
- **鼠标光标**：
  - 使用鼠标高亮软件（如 PointerFocus）
  - 光标大小适中，点击时有视觉反馈
- **按键显示**：
  - 使用屏幕按键显示工具（如 KeyCastr、NohBoard）
  - 显示快捷键操作（Ctrl、Shift、Alt）
- **参数标注**：
  - 重要参数用文字标注（如"半径：10"、"间距：5"）
  - 箭头指向操作区域
  - 使用醒目但不刺眼的颜色（黄色、青色）

#### 节奏控制
- **操作速度**：
  - 演示时放慢速度，给观众反应时间
  - 重复操作可适当加速（配合说明）
  - 复杂步骤分段演示，每段后暂停讲解
- **过渡与等待**：
  - 每个操作完成后停留 1-2 秒
  - 切换工具时给予明确提示
  - 避免快速跳转造成观众迷失

---

### 音频质量

#### 旁白录制
- **语速与清晰度**：
  - 语速适中（140-160 字/分钟）
  - 吐字清晰，避免含糊
  - 专业术语首次出现时强调
- **语气与情感**：
  - 热情友好，像在指导朋友
  - 避免机械朗读或过于兴奋
  - 适当停顿，强调重点
- **脚本准备**：
  - 提前写好脚本或大纲
  - 关键步骤逐字稿，过渡部分自由发挥
  - 录制前多次演练

#### 音频后期
- **降噪**：去除环境噪音、电流声
- **均衡器**：增强人声清晰度
- **压缩器**：统一音量，避免忽高忽低
- **背景音乐**：
  - 音量：-20dB 至 -25dB（不抢戏）
  - 类型：轻柔、无歌词、节奏平缓
  - 建造场景可用 Minecraft 原声音乐

### 内容结构

#### 标准开场（每集）
1. **片头动画**（5-10 秒）
   - Plot Logo + 教程标题
   - 统一模板，建立品牌识别
2. **本集概述**（30-60 秒）
   - "大家好，欢迎来到 Plot 教程第 X 集"
   - 本集主题和学习目标
   - 前置知识提醒（如需要）
3. **上集回顾**（可选，30 秒）
   - 快速回顾上集重点
   - 承上启下

#### 主体内容结构
- **理论讲解**（20-30%）
  - 工具/功能的作用和原理
  - 参数的含义
  - 使用场景
- **操作演示**（50-60%）
  - 分步骤演示
  - 边操作边讲解
  - 重点操作重复演示
- **实战案例**（20-30%）
  - 综合应用所学工具
  - 完成具体建造任务
  - 展示最终成果

#### 标准结尾（每集）
1. **知识点总结**（30-60 秒）
   - 快速回顾本集重点
   - 3-5 个要点列表
2. **下集预告**（15-30 秒）
   - 下集主题简介
   - 激发观众期待
3. **互动引导**（15-30 秒）
   - 鼓励点赞、评论、分享
   - 提问或作业（可选）
   - 社区链接（Discord/QQ 群）
4. **片尾动画**（5-10 秒）
   - 感谢观看
   - 订阅提醒

## 视觉设计规范

### 文字标注
- **字体**：
  - 中文：思源黑体 / 微软雅黑（Bold）
  - 英文：Roboto / Open Sans（Bold）
  - 大小：36-48pt（1080p），48-64pt（1440p）
- **颜色方案**：
  - 主要文字：白色带黑色描边（厚度 3-4px）
  - 强调文字：黄色 (#FFD700) 或青色 (#00CED1)
  - 警告提示：红色 (#FF4444)
  - 成功提示：绿色 (#00FF00)
- **位置**：
  - 标题：屏幕上方 1/5 处
  - 步骤说明：屏幕下方 1/4 处
  - 参数标注：紧贴操作区域

### 图形元素
- **箭头**：
  - 指向操作位置
  - 动画：淡入 + 缓动
  - 颜色：与文字标注配套
- **高亮框**：
  - 圆角矩形，半透明填充
  - 描边 3-5px
  - 用于突出工具栏按钮或参数
- **放大镜效果**：
  - 关键操作时局部放大
  - 圆形或矩形遮罩
  - 2-3 倍放大，边缘羽化

### 过渡效果
- **场景切换**：
  - 简单淡入淡出（0.5-1 秒）
  - 避免复杂转场
- **章节分隔**：
  - 全屏标题卡（2-3 秒）
  - 背景：Plot 截图模糊处理
  - 文字：清晰醒目

## 常见问题处理

### 录制中的技术问题

#### 性能问题
- **卡顿**：
  - 降低渲染距离
  - 关闭光影和不必要的模组
  - 使用性能优化模组（Sodium、Lithium）
- **录屏掉帧**：
  - 降低录制分辨率或帧率
  - 使用硬件编码（NVENC、AMD VCE）
  - 关闭后台程序

#### 操作失误
- **点错工具**：
  - 保持录制，自然纠正
  - 说明"刚才不小心点错了，我们重新来"
  - 后期可剪辑掉长时间的失误
- **参数设置错误**：
  - 对比展示错误和正确的效果
  - 变失误为教学点："注意这个参数如果设置错了会..."

#### 画面问题
- **界面被遮挡**：
  - 调整 Minecraft 窗口大小
  - 移动 Plot 面板位置
  - 使用 F1 隐藏游戏 HUD
- **光线不足**：
  - 游戏内时间调至白天（/time set day）
  - 增加亮度设置
  - 放置额外光源（火把、灯笼）

## 后期制作

### 剪辑流程
1. **粗剪**：
   - 删除长时间停顿、失误、无关内容
   - 保留完整的操作流程
   - 标记重点片段
2. **精剪**：
   - 调整节奏，加快重复操作
   - 添加转场效果
   - 同步音频和画面
3. **特效与标注**：
   - 添加文字标注
   - 插入箭头、高亮框
   - 放大关键操作
4. **音频处理**：
   - 降噪、均衡、压缩
   - 添加背景音乐
   - 音效（鼠标点击、成功提示音）
5. **色彩校正**：
   - 统一色调
   - 增强饱和度和对比度
   - 确保文字清晰可读

### 字幕制作
- **时间轴精确**：字幕与语音同步
- **分段合理**：每句 2-3 秒，不超过两行
- **双语对照**：
  - 中文在上，英文在下
  - 或左右分栏
- **关键词高亮**：工具名称、参数用不同颜色

### 输出设置
- **格式**：MP4（H.264）
- **分辨率**：1920x1080 或 2560x1440
- **帧率**：30 FPS 或 60 FPS
- **码率**：8000-12000 kbps（视频），192-256 kbps（音频）
- **平台优化**：
  - YouTube：上传前检查版权音乐
  - Bilibili：调整为平台推荐参数

## 最佳实践总结

### 成功要素
1. **内容为王**：准确、完整、实用
2. **视觉清晰**：操作可见、标注明确
3. **节奏舒适**：不快不慢，留出思考时间
4. **案例精彩**：实用且美观
5. **持续更新**：保持发布节奏
6. **积极互动**：回复评论，收集反馈

### 避免的坑
1. **音质差**：背景噪音大、音量不稳定
2. **节奏过快**：观众跟不上操作
3. **缺少标注**：关键参数看不清
4. **案例丑陋**：最终成果缺乏吸引力
5. **断更**：长时间不更新失去观众
6. **不互动**：忽视评论和反馈

### 进阶技巧
- **A/B 测试**：尝试不同风格的封面、标题
- **数据驱动**：根据观看数据优化内容
- **跨平台推广**：在多个平台同步发布
- **联动合作**：与其他 Minecraft 创作者合作
